# 28 · 不良反应段内锚定摘录（「伤肝吗」类问题）

> 2026-11-20。状态：**已实现（api）并部署 staging（见 §6）**。
> 触发：用户截图——问「磷酸奥司他韦这个药伤肝吗」，回答卡结论是
> 「1.临床试验 由于本品的临床试验是在各种不同条件下进行的…」，「需要知道」是精神神经性不良事件。

## 1. 现象与根因

- **路由是对的**：`SECTION_ROUTES` 的 `adverse` 规则命中「伤肝」，取整段不良反应（该说明书 2784 字）。
- **拼装只取段首**：`fallbackSectionsFromInsert` 的 summary = 段首 90 字（截图那版是 120 字），
  而这段开头是临床试验免责句，与「肝」无关。
- **「需要知道」与问题无关**：固定取注意事项前 3 条 → 精神神经性不良事件（该说明书注意事项里没有「肝」字）。
- **真正答案在段内 97% 处**：「…全身：…消化系统：肝炎、肝功能检查异常心脏：心律失常…」（上市后经验，
  自发报告、频率无法估算）。按段首截断永远截不到。
- **数据形态坑**：PDF 抽取入库后段落没有换行，器官标签粘在上一条正文末尾
  （`…体温过低皮肤：皮疹…多形性红斑消化系统：肝炎…`），只按换行/句号切不开。

## 2. 方案（不生成、只抄录）

`pickAnchoredExcerpt(question, section)`（`app/packages/api/src/services/consult/sections.ts`）：

- 只在 `section.key === 'adverse'` 且问题命中话题白名单（肝/肾/胃肠/犯困/头晕/头痛/皮肤/血糖/血液）时生效；
- 段内切分顺序：换行 → `。；` → 器官标签（MedDRA 系统器官名，长标签优先，解决标签粘连）；
- 命中片段（≤2 条）作为 summary，措辞为「说明书在不良反应的『上市后经验』中列有：…」（标明小节来源）；
- 「需要知道」只留含同一关键词的注意事项（≤3 条、仍按 64 字摘要）；没有就留空，不用适应症兜底；
- **人话解释层（2026-11-20 用户反馈「这句话什么意思」）**：不改写医学结论，只解释行话与边界——
  ① 小节是「上市后经验」时固定补一句「上市后经验是药品上市后医生/患者自发上报的不良事件，
  发生频率无法估计，不等于每个人都会出现」；
  ② 没有相关注意事项时补「如有相关基础疾病，或正在同时使用其他药物，建议先咨询医生」；
- 段内确实没有相关原文 → summary 明说「本地说明书的『不良反应』段未见与『X』相关的描述」，不拿无关段落充数；
- 其它段落（相互作用/注意事项/禁忌…）与非锚定问题（如「有什么副作用」）行为完全不变。

例：`这个药伤肝吗` → 结论「说明书在不良反应的「上市后经验」中列有：消化系统：肝炎、肝功能检查异常。」，
「需要知道」，「上市后经验是…自发上报…不等于每个人都会出现」+「如有相关基础疾病…建议先咨询医生」；
原文仍在「展开原文」里。

**症状类问句（2026-11-20 补）**：`肝痛 / 肝区 / 肝疼 / 肝病` 也命中不良反应段（此前不含任何路由词，
和「说明书」一起掉进适应症兜底，两句回答一模一样）；问句含 `痛 / 疼 / 不舒服 / 胀 / 酸` 时，
nextAction 固定为「说明书未把您描述的症状列为用药条件；请先就医明确原因，是否服用请遵医嘱」，
不给「能不能吃」的结论。

## 3. 边界

- 只覆盖 L0/降级规则拼装（未核验说明书 + 模型不可用）；reviewed 走 LLM 的路径不变（prompt 仍注入整段）。
- 锚定词表是白名单：新增话题必须同时在 `consult-sections.test.ts` 加用例。
- 不做「伤X」的泛化抽取：避免把「伤」字的无关同义句抽出来当结论。
