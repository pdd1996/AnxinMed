## 0. 与 05 任务书 / web 现状的口径差（先看，不要自行裁决）

1. **「拒拍」二字与全线设计相反。** `05:111` 写「质量预检**拒拍**场景…反馈正确」，但预检在本项目**从不拦人**：core 的接缝注释原文是「预检只是建议，不拦用户」（`core/src/lib/intake.ts:170-171`），web 的预检卡永远给两颗钮——「重拍 / 换一张」和「仍要上传」（`web/src/components/domain/intake/IntakeFlow.tsx:259-264`）。
   **处置**：本片按**「触发重拍建议的场景」**解释那句，任何把预检做成闸门的写法一律返工。
2. **「缺角」在本仓库没有任何判据实现。** 全仓 grep「缺角」零命中，唯一出处就是 `05:111` 那一句；`assessQuality` 只有四项（`too-dark / glare / blurry / too-small`，`core/src/lib/intake.ts:175,195-202`），「单子摊平拍全」是**拍摄引导文案**（`web/src/routes/patient/IntakeRx.tsx:7`）不是检测。版面完整度检测在 web 不存在、无阈值无文案无测试。
   **处置**：不在 T6 造新机制；缺角的实际归宿是服务端 OCR 抽不出内容 → `mapIntakeFailure` 兜底卡「无法可靠识别」+ `RETAKE_CHECKLIST`（`core/src/lib/intake.ts:148-153`）。**用户若坚持要缺角检测，属新判据，另立案**（要新阈值 + 新文案 + 重跑 A/B 基线）。
3. **入口 A 的 tab 与入口 A 的确认页不可分家——这是本片最硬的依赖。** core 的闸门函数 `unmetReasons` 在 `payload.planDraft` 存在时最多追加**九条**（用量值 / 频次值 / 时间点 / 开始日期 + dose/frequency/duration 三处「已核对」勾选 + 自定义疗程天数），处方类（`payload.type==='prescription'`）还恒加一条「请确认这盒药的使用人」（`core/src/lib/draft.ts:242-259`）。RN 的草稿页今天**这些控件一个都没有**（`mobile/src/app/drafts/[id].tsx:290-299` 只自造了一句「用法用量（本照片不含）」），于是：**只做 tab 而不做确认页 = A 入口能拍、能识别、能列出草稿，但确认钮永远点不动**。
   **处置**：T6-a 的验收**明确不含**「A 端到端确认成功」，那条归 T6-d；两片的完成标准分开写死。
4. **「点按即切」在 RN 要用 `replace` 不是 `push`。** web 的两个入口是**两个路由**（`web/src/router.tsx:32-34` → `/intake/rx`、`/intake/drug`），点另一个 tab = 跳到对方页面（`IntakeFlow.tsx:185` → `goto_other_entry` → `core/src/intakeFlow/flow.ts:261-262` 纯 navigate，**无确认弹窗、无二次提示**），页面重挂所以上传态自然归零。RN 若 `router.push` 会留栈（物理返回回到刚离开那一屏、且带着半截状态），语义不等价。
   **处置**：`router.replace`，并登记进差异清单为「刻意同义、实现不同」。
5. **平级 tab 不是底部 tabBar，也非「收起动画」**：web 的两颗 tab **只在 upload 步渲染**（`IntakeFlow.tsx:175-197` 条件渲染，出了 upload 就没了 = 任务书说的「照片进流程后 tab 收起」），眉题「拍照录入」常驻（`:171`）。
   **处置**：mobile 照 web 用两颗大 `Pressable`（**别**套 `components/ui/tabs.tsx`，那套 `@rn-primitives/tabs` 是设置页的分段控件，形态与语义都不对）；`step !== 'upload'` 时不渲染。
6. **质量预检在 RN 是「二期补实现」，且二期比 T2 当初预估的重。** `05` T2 第 2 条允许 RN 一期降级（现值：`compute_stats` 直接回 `null`，`mobile/src/app/intake.tsx:74-78`，于是 `quality` 分支 `:217-229` 是死代码）。起草时实测取证：`expo-image-manipulator` SDK 57 线 = **57.0.21**（`npm view expo-image-manipulator dist-tags` → `sdk-57: 57.0.21`，`latest` 同值），**它没有任何 raw pixel 接口**——`npm pack` 解包读 `build/ImageManipulator.types.d.ts` / `ImageRef.d.ts` / `ImageManipulatorContext.d.ts`，只有 `renderAsync()` → `ImageRef{width,height,saveAsync(options)→{uri,width,height,base64?}}`，三个文件 grep `pixel` **零命中**。
   **结论**：RN 要出统计值必须走**两跳**——原生 resize 到 ≤512 边长 → 拿到小图 base64 → **JS 侧解码**（纯 JS 包，如 `jpeg-js@0.4.4`）→ 喂进与 web 同一套数学。**代价：1 个原生依赖（要重出包装机 + v2rayN 在线，见 §7）+ 1 个 JS 解码依赖 + 一处 core 接缝签名放宽（§1-3）。** 三条路列进 §0.1 D1。
7. **「草稿中断恢复」在 web 只到「同一会话内」，服务端根本没有找回入口。** 原图内存即用即弃且**明写绝不 persist**（隐私红线 `core/src/stores/intakeSession.ts:1-15`）；API 只有 `GET /api/drafts/:id` + confirm + reject（`api/src/routes/drafts.ts:15-24`），repo 只有 `listDraftsByIds`（`api/src/repositories/drafts.repo.ts:25`），**没有「按用户列出 pending」的查询，web 也没有草稿列表页**（草稿清单是录入组件内的一个 step，`IntakeFlow.tsx:400-465`）。
   所以 `05:111` 那句「中断恢复可用」要么是**照 web 现状**（会话内交接 + 返回语义，零后端改动），要么是一个**web 没有对照物的新功能**（服务端列表接口 + shared 契约 + 收件箱屏 + 测试）。→ §0.1 D2。
8. **T4 的两条判命项至今挂着，而 T6 是唯一必须大量真人拍照的片。** `mobile/T4-真机验收.md:11-13`：真机端到端 🟡「模拟器已通、真机未跑」、三种失败反馈 ⬜、**A/B 基线 ≥10 张 ⬜**（那条是 05 §9 止损线 1 的判命数据）。
   **处置**：并进 T6-f 一起收。**同时口径要改一处**：`app/e2e/ab-baseline/README.md:13,15,41` 现在写着「RN 一期不做预检 → 预检触发列天然不等、不可用于判止损」——D1 若选「完整预检」，这一列**变成可比**，表头与结论句要同步改，否则拿旧口径判新数据。
9. **mobile 至今零测试。** `packages/mobile` 无任何 `*.test.*`、无 RNTL/vitest/jest devDep，`package.json` 没有 `test` script；而 05 §测试策略 的「新增：mobile RNTL 关键组件测试」还没起步。web 侧现成可抄的范式就在 `web/src/components/domain/intake/IntakeFlow.test.tsx:211-228`（stub 统计值 → 断言预检卡与「仍要上传」）。→ §0.1 D3。
10. **今日页那张「网络探测」入口卡**（`mobile/src/app/(patient)/index.tsx:57-62` → `/probe`）是 T3 的验收产物，如今与「拍药盒入药箱」并排常驻患者首页；同页 `:64` 的 SOON 卡「拍处方笺（含用法用量）· M5-T6」本片要换成真实入口。→ §0.1 D4。

## 7. 已知风险（提前登记，翻车不算意外）

1. **统计数学两处实现分叉**（web canvas 那份不动 + RN 新解码一份）：唯一护栏是同源自 `assessQuality` 的四个阈值 + 手算 fixture 单测 + 注释互指。**后果自负的形态**是「RN 判模糊、web 不判」这种说不清的差异——出现时先比 stats 原始值（同图各端打日志），别先改阈值。
2. **解码内存与耗时**：禁全尺寸解码（46MB RGBA 级别）；resize-first 是硬约束。低端 ROM 上若解码耗时 >1.5s，按 §2-T6-b spike 门槛降 D1-B 档并如实登记，不许「顺手」把预检挪到上传后（那是服务端的事）。
3. **新原生依赖 → 出包链路**：v2rayN 必须在线（Gradle 钉 `socks 127.0.0.1:10808`，05d §7-2）；`expo prebuild` 会先删 `android/`（被 Gradle 占住报 EBUSY），`android/` 不入 git，删了要 prebuild + 三个镜像补丁重建（README:168-170）。
4. **alpha 令牌类静默丢失**：本片新组件里 `bg-muted/40`、`border-risk-l3/40`、`text-primary-foreground/80` 这类**一律禁写**（05d §7-7、README:118-136；`intake.tsx:183` 与 `drafts/[id].tsx:275` 是现存两处漏网，本片顺手收掉）。图标颜色走 `useUnstableNativeVariable("--x")` 显式给。
5. **闸门与隐私红线不可放宽**：预检不拦人（§0-1）；无「一键全部确认」（§6-9）；原图不落 persist、新接口不回图片字节（§2-T6-e）。违反任一条即返工，不接受「为了体验」。
6. **写操作会污染演示库**：连确两份草稿、confirm 落库都会往公网演示库写真数据，且**没有 records 删除接口、记录写入不可改**。动手前先确认快照落 `app/backups/`，回清 SQL 与列名口径（`plan_id`/`scheduled_date` 是 snake_case）照 T5 §2.12「数据副作用」那段改日期再跑。
7. **装机与包体口径**：任何「装机事实」带 Host（两台机都能出包，不标就没法复盘是哪台的屏幕）；这台 ColorOS 上 `adb uninstall` 不一定清数据，验首启态「一次卸载重装不算数」（T5 §2.13）；跨机 pull 后 router 生成物过期导致的 typecheck 红不是代码错（§1-6）。
8. **T6-a 的「A 入口可用」容易被误写成完成**：按 §0-3，A 端到端只在 T6-d 之后才成立；若在 T6-a 之后有人问「A 能不能用」，答「能拍能识别、确认钮永远禁用」，并给出 `draft.ts:242-259` 的行号，不要含糊。
