## §0 目标与边界

**目标**：

1. **demo 数据卫生**：清掉 p-001 下 3 条重复的海露 `drugs` 行（测试残留，无 plan/record/risk_event/draft 引用），保留在用的 transcribed 行；**不把 4 个 manual 演示药改成 ocr_matched/transcribed**——那会伪造 OCR 核对事实，宁可让 manual 门禁如实存在。
2. **模拟 runbook**：零模型 key 的 fixtures 路径，覆盖三条用户路径：拍照入库 → L1 咨询 / 手动建档 → L0 门禁 / 生效计划 → 相互作用（demo 条目 + 徽章）。给出命令、预期结果、观察指标、失败分支。
3. **规则候选池**：扫 230 行 reviewed PDF 说明书的【药物相互作用】段，产出逐字候选（pair + quote + 来源 + 建议分级），交人工签核；**不入库、不改 seed**。

**明确不做**：

- 不改 `confirm_status` 伪造核对；不改 `reviewed` 状态；不新增 curated 规则；
- 不改咨询 prompt / 守门规则 / web 患者端 UI；
- 不碰 `promo/`（宣传片工程，独立提交）；
- 本次候选池只覆盖 reviewed PDF 行；DXY 15 行相互作用段缺失（M8 已登记）不在挖掘范围。

## T1. demo 数据卫生 + 模拟 runbook

**做什么**

1. `db:cleanup-demo-drugs`（`src/scripts/cleanup-demo-drugs.ts` + 纯函数规划器）：
   - 目标：`user_id='p-001'` 且 `drug_master_id='drug-hycosan-01'` 的 **未引用重复行**；
   - 引用检查：`plans.drug_id`、`risk_events.drug_id`、`drafts.payload::text`；任一引用 → 拒绝删除该行；
   - 保护：至少保留 1 行；被引用的行永不删；默认 dry-run，`--apply` 单事务；
   - 报告：`data/m9-reports/cleanup-demo-drugs.json`（本地）。
2. 模拟 runbook `docs/specs/09-M9-模拟运行手册.md`：
   - 启服务：`cd app && AI_MODE=fixtures pnpm dev`（api 8787 + web 5173）；
   - 场景 A 拍照入库（`app/fixtures/rx-normal.png`）→ 草稿 → 确认 → 药箱/计划 → 咨询 L1；
   - 场景 B 手动建档药咨询 → 只 L0（manual 门禁文案可见）；
   - 场景 C p-001 生效计划 → 相互作用检查命中 demo 条目（移动端徽章/网页文案）；
   - 每场景列：步骤、预期、失败分支、观察指标（耗时/错误码/是否静默）。
3. 验证：清理前后 counts；`db:audit`；consult 门禁用例（manual → L0、reviewed+transcribed → 非 manual-gate）用现有集成测试/新增 1 条纯函数或集成断言。

**完成标准**

- 3 条重复行删除（或 dry-run 报告证明不可删原因），p-001 `drugs` 8 → 5；transcribed 行与 4 个 manual 行保留；
- `plans/records` 数量不变，无外键/孤儿；
- runbook 三场景可照做，fixtures 路径不需要任何 key；
- 单测/集成断言覆盖「manual 不因 reviewed 而放行 L1」。

## T2. 规则候选池（230 reviewed PDFs）

**做什么**

1. `db:rule-candidates`（`src/scripts/rule-candidates.ts`）：
   - 输入：`curation_status='reviewed'` 且 `source like '说明书 PDF%'` 的说明书行；
   - 只取 `sourceSections['药物相互作用']`（允许变体），按句切分；
   - 别名索引：`drug_master.generic_name` / `brand_name` + 去剂型/盐基后缀变体（长度 ≥3），排除与来源药同通用名的自指；
   - 命中句 → 排除「无影响/不改变/未见」类陈述，保留风险句；按 PRD 四级做确定性建议（禁用→禁忌 / 慎用→慎用 / 监测→需监测 / 其余→注意）；
   - 输出每条候选：来源 insertId/drugId/sectionKey/version、逐字 quote、提及药 concept + 候选 drugIds、建议 level、命中标记；去重（来源药 + 提及 concept + quote）；
   - 不做：不改库、不写 seed、不自动选 ID。
2. 报告 `data/m9-reports/rule-candidates.{jsonl,md}`（本地）+ 汇总：扫描行数、命中句数、候选数、按建议分级分布、Top 配对、噪声说明。
3. 文档记录：候选池的**已知噪声**（类别名/复方/别名歧义、规则 flat drugIds 需全选才能命中的限制）与**签核流程**（人工逐条确认 quote/分级/来源后，才进 M9 之后的规则库任务）。

**完成标准**

- 230 行扫描完成、0 解析失败；候选至少覆盖若干常见高风险对（如华法林/阿司匹林/他汀类）；
- 每条候选 quote 是原文逐字子串（脚本自检 100%）；
- 报告可复算；明确「本任务不让任何候选进库」。
