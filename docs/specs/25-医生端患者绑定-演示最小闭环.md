# specs/25 · 医生端患者绑定（方案 A：演示最小闭环）

> 日期：2026-11-19
> 性质：**演示切片**。为 2026-11-20 演示补齐「医生端与患者建立联系」的最小可点通闭环；
> 不是完整医患关系系统，也**未**进入 PRD V2.4 正式范围。
> 前置：G7 账号密码登录（specs/13）、ADR #12（医生端演示保留）、ADR #17（队列只读工具）、
> ADR #23 第 1 条（医生端 Agent 作用域 = 该医生的授权患者队列）。
> 范围：`app/` 代码 + 本机演示库 + 本文档；**未部署 staging**（SSH 凭据仍不可用）。

---

## 0. 一句话

医生生成一次性 6 位绑定码 → 患者在自己账号里输入确认 → 医生端队列只出现「已授权患者」；
患者可随时解绑；医生端接口与数据作用域由服务端按绑定关系裁决（demo 模式整体旁路，保证既有测试/E2E 零回归）。

## 1. 为什么是切片，缺什么

**已实现（本切片）**

| 能力 | 说明 |
|---|---|
| 角色字段 | `users.role`：`patient`（默认）/ `doctor` |
| 绑定关系 | `doctor_patient_links`（status = active/revoked，解绑保留历史） |

| 患者端 | 设置 →「我的医生」：输入绑定码、查看已绑定医生、两步确认解绑 |

## 2. 数据模型（迁移 `0014_tiny_hellfire_club.sql`）

`users` 增列：

| 列 | 类型 | 说明 |
|---|---|---|
| `role` | varchar('patient' \| 'doctor')，默认 `patient` | 只用于医生端角色闸门，不做业务档案 |

`doctor_patient_links`（唯一索引 `doctor_id, patient_id`）：

| 列 | 说明 |
|---|---|
| `status` | `active` / `revoked`（解绑保留历史，不物理删除） |
| `source` | `bind-code`（患者核销）/ `seed`（演示预置） |
| `bound_at` / `revoked_at` | 授权生效/解除时间 |

`doctor_bind_codes`：`code`（6 位，唯一）、`doctor_id`、`expires_at`、`used_at`、`used_by_patient_id`。
医生重新生成时删除其未使用旧码。

## 3. API 契约（shared/src/binding.ts 一份真相）

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| `POST /api/doctor/bind-code` | 医生 | 生成绑定码 → `{ code, expiresAt, ttlSec }` |
| `GET /api/bindings` | 登录 | 患者「我的医生」→ `{ doctors: [{id,name,boundAt}] }` |
| `POST /api/bindings/redeem` | 患者 | `{ code }` → `{ doctor }`；无效/过期 400、已绑定 409、医生调用 403 |
| `DELETE /api/bindings/:doctorId` | 患者 | 解绑；无有效绑定 404 |
| `/api/insight/*` | 医生 | 全部按当前医生 active 绑定过滤；单患者未授权 → 404 |

错误码：`FORBIDDEN`（新增，角色不符 → 403）、`VALIDATION`、`NOT_FOUND`、`CONFLICT`。

**demo 模式旁路**：`AUTH_MODE=demo` 时角色闸门与作用域过滤整体旁路 —— 既有 39 条 insight 测试与
fixtures E2E 的医生端断言（队列 16 人 / 分档数字）逐字不变。这是本切片最重要的兼容约束。

## 4. 演示准备（本机）

### 4.1 医生端专用登录入口 `/doctor/login`

医生与患者共用同一账号体系，但入口分开：

- `/login`：患者端登录（页面底部有「医生端登录」链接）；
- `/doctor/login`：医生端专用登录页（公开路由）——账号密码登录，登录后用**服务端返回的 role**
  判断：非 `doctor` 账号即使密码正确也会被登出并提示「该账号不是医生账号」，不依赖前端隐藏入口；
- 未登录直接打开 `/doctor/insight` → 自动跳 `/doctor/login`（登录成功后回原页）；
- 已登录的医生从任意入口进入医生端均可；医生端头部显示当前医生 + 退出登录（退出回 `/doctor/login`）；
- demo 模式（`AUTH_MODE=demo`）保持既有旁路：`/doctor/insight` 直接可进（fixtures E2E 零回归）。

### 4.2 启动与账号

```powershell
# 1) 一次性准备：开通医生/患者账号 + 预绑定演示患者（幂等）
cd app
pnpm --filter @anxin/api demo:setup-doctor
#    医生：doctor-demo / AnxinDemo2026（role=doctor，id=doctor-demo）
#    患者：p-001 / AnxinDemo2026（seed 演示数据：5 药 / 179 打卡）
#    预绑定：p-101…p-107（有打卡数据）→ 医生队列初始 7 人
#    p-001 故意不绑定 → 现场演示「绑定后从 7 变 8」

# 2) 启动（password 模式；两个终端）
cd app
$env:AUTH_MODE="password"
pnpm --filter @anxin/api dev      # :8787
pnpm --filter @anxin/web dev      # :5173
```

> 演示要用**两个身份**（demo 模式固定注入 p-001，做不到双身份），所以必须 password 模式。
> 两个浏览器窗口需隔离登录态：一个普通窗口 + 一个无痕窗口（或两个浏览器）。
> ⚠️ 启动前先停掉正在跑的 `pnpm dev`（8787/5173），否则旧进程仍以 demo 模式占端口，新命令会因端口冲突
> 落空或前端代理到旧进程（表现：打开即 p-001、无登录页）。

**演示动线（约 2 分钟）**

1. 医生窗口：`http://localhost:5173/doctor/insight` → 登录 `doctor-demo` → 队列 7 人（分档图 + 患者表）；
2. 点「生成绑定码」→ 屏幕出现 6 位码 + 倒计时；
3. 患者窗口：`http://localhost:5173/login` → 登录 `p-001` → 设置 →「我的医生」→ 输入绑定码 → 绑定成功；
4. 医生窗口刷新 → 队列变 8 人，列表出现「张某某」；
5. （可选）患者点解绑 → 医生刷新 → 恢复 7 人；用 403/404 讲「越权不可见」。
6. 被问「怎么建立联系」时的口径：这是**试点前最小授权闭环**（患者确认 + 可解绑 + 服务端作用域）；
   完整角色/机构/审计模型见 §1「未做」。

**恢复 demo 模式**：停服务 → 去掉 `AUTH_MODE`（或设为 `demo`）→ 重启；演示账号数据保留、不影响既有演示。

## 5. 安全与已知风险

1. **绑定码可被枚举**：6 位数字 + 无核销失败限流 = 演示可接受；**上线前必须**加按患者/IP 的失败限流与审计。
2. 绑定关系无独立审计表（B 方案补）；解绑保留 revoked 行可追溯，但操作人/时间只落 updated_at。
3. demo 模式旁路意味着本地 demo 无角色隔离（与既有行为一致，属演示语义）。
4. H5 冻结偏差：患者端「我的医生」卡片加在 web 患者端设置页（05 任务书冻结「web 患者端任何功能新增」）。
   **仅为本次演示临时解冻**；正式形态应落在 APK（M5 起主力）。
5. 绑定码明文只在生成响应出现一次，但 DB 存 code 明文（短 TTL、一次性；B 方案可改哈希）。
6. 医生账号仍可登录患者端（角色只收窄医生接口，不做前端全站隔离）——演示口径，非权限模型完整实现。
