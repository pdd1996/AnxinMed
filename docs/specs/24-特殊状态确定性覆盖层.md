# 特殊状态确定性覆盖层 · 实现任务书（24）

> 来源：PRD V2.4 §7.1.2「字段消费通道」/ §12.5「Agent 数据边界与隔离」· ADR #23 · 架构 [docs/12 §3.4 / §4.1 S4](../12-安心用药-Agent整体架构.md)（V1.1 已同步）
> 前置范式：M4-T4 过敏确定性覆盖层已验收 —— [allergy.ts](../../app/packages/api/src/services/consult/allergy.ts) 可直接作模板（同签名、同位置、同守门纪律）。
> 状态：**未落地**（2026-11-19 立项；里程碑编号与排期待确认，本文按 M15 建议）。
> 边界：不新增 LLM 调用、不改 prompt 通道、不改既有咨询行为；仅新增一条确定性覆盖层 + 档案白名单扩一字段。

## 1. 目标与边界

**目标**：把档案「特殊状态」（自由文本：孕期 / 哺乳期 / 肝肾功能不全 / 植入器械等）与对象药说明书的禁忌段、注意事项（慎用）段做**确定性交集**；命中 → 回答分区追加固定警示 + 对应段落引用。

**不做**（与 S4 过敏覆盖层同构，逐条验收）：

- 不进模型上下文（prompt 里不得出现特殊状态值）；0 次 LLM；
- 不改 `riskLevel`、不写 `risk_events`（提示非拦截）；
- 不做医学推断 / 模糊联想（不把「孕期」推出「致畸风险」，只陈述「与该药禁忌段相关」）；
- 不给剂量调整、停药换药建议；不替代医生判断；
- 不作用于 S0 固定文案、S2 数据直答、`clarify` / `out-of-scope`（无禁忌段上下文）；
- 不覆盖「紧急联系人」等通道表外字段（PRD §12.5 字段边界）。

## 2. 设计

### 2.1 字段与提取

- 字段键：`特殊状态`（`@anxin/shared` 的 `HEALTH_FIELDS` 已在册，档案页已有输入框，`HealthInfoCard` placeholder「如：孕期、安装心脏起搏器」）。
- `extractSpecialStatusKeywords(rows)`：只取该 `fieldKey`；按 `/[,，、;；/\s]+/` 拆分；trim；归一化后长度 ≥2 保留；去重。与 [allergy.ts `extractAllergyKeywords`](../../app/packages/api/src/services/consult/allergy.ts) 同口径。

### 2.2 同义词（字形等价，非医学推断）

自由文本与说明书用词不一致是主要漏判来源（用户填「怀孕」、说明书写「孕妇禁用」）。集中一张**可审计的字形等价表**，只做词形映射、不做医学判断：

```ts
// 只做字形等价；新增条目必须人工复核（同规则库纪律：不生成、只抄录词形）
const SPECIAL_STATUS_SYNONYMS: Record<string, string[]> = {
  孕期: ['孕妇', '妊娠', '怀孕', '孕产期'],
  哺乳期: ['哺乳', '哺乳期妇女', '母乳喂养'],
  肝功能不全: ['肝功能不全', '肝功能损害', '严重肝病'],
  肾功能不全: ['肾功能不全', '肾功能损害', '严重肾病'],
  透析: ['血液透析', '腹膜透析'],
  起搏器: ['起搏器', '心脏起搏器'],
}
```

匹配规则：档案 token 先按同义词表归一为 canonical（等值匹配）；未命中映射的 token 按原词参与匹配（与过敏层一致）。**宁漏勿误**：否定表达（「未怀孕」「无过敏史」）按整词子串匹配天然不命中，属可接受漏判，不做语法解析（会引入误报）。

### 2.3 匹配目标与纯函数

- 匹配目标：`insert.contraindications`（禁忌）与 `insert.precautions`（注意事项/慎用）；两者都是 jsonb（`string[] | string | null`）。
- 实现 `specialStatusOverlay(keywords, contraindications, precautions, sections, citations)`：
  - 无关键词 / 无段落文本 / citations 为空 → 原样返回（同一引用，不产生新对象）；
  - 命中禁忌 → `sections.risks` 追加一条固定警示 + citations 追加 `sectionKey='contraindication'`（`sectionLabel='禁忌'`）；
  - 仅命中注意事项 → 追加一条固定警示 + `sectionKey='precautions'`（`sectionLabel='注意事项'`）；
  - 两类都命中 → **只追加一条**警示，引用取禁忌段（强度优先）；
  - 固定文案（单条，canonical 全列）：`特殊状态提示：你的档案特殊状态（孕期）与该药禁忌相关，请核对禁忌并咨询医生或药师。`（注意事项命中时把「禁忌」换成「注意事项」）。
- 复用：把 allergy.ts 的私有 `narrowContraindications` 抽成共享纯函数 `narrowInsertText(v)`（如 `consult/insertText.ts`），allergy / specialStatus 共用；纯重构，既有单测断言不变。

### 2.4 接线（位置纪律）

- `consult.service.ts` 5c 过敏覆盖层之后顺序执行（5d 引用完整性校验之前）；命中后同样把 `{ drugName, sectionKey }` 登记进 `result.evidence.sections`，供 citation coverage 校验（与 M4-T9 同口径）。
- 作用条件：`status ∈ {answered, limited, manual-gate}` 且 `result.sections` 存在且有 `insert`。
- **引用去重**：allergy 与 special-status 可能同时锚定 `contraindication` → 追加后按 `(drugName, sectionKey)` 去重（保留首次）。总追加警示 ≤2 条（每层各 1 条）。
- 档案读取白名单：`consult.service` 的 profiles 白名单从「过敏史 / 诊断」扩到「过敏史 / 诊断 / 特殊状态」，并更新注释；**该字段只进确定性层，绝不进 prompt**。
- 开关：新增 `ENABLE_SPECIAL_STATUS_OVERLAY`（默认开，`false` 一键整体回滚；与 `ENABLE_SCOPE_GATE` / `ENABLE_OBJECT_CLARIFY` 同风格）。

### 2.5 隐私

特殊状态值属于敏感健康信息：只在固定警示文案中原样回显给用户本人；不写日志、不落库新增字段、不进第三方请求体；请求体白名单断言必须覆盖「特殊状态值不出现」。

## 3. 测试与验收

**纯函数单测（≥10 例）**：命中禁忌 / 命中注意事项 / 两者同中 / 不命中 / 无档案 / 段落缺失 / 多值拆分 / 同义词映射（怀孕→孕妇）/ 否定表达不命中（未怀孕）/ 大小写与拉丁词 / citations 空防御。

**集成（`app.request()` 或 service 级）**：

1. 档案特殊状态 = 孕期 + 对象药禁忌含「孕妇禁用」→ 回答内容逐字不变，仅追加固定警示 + 禁忌段引用；`citations` 去重；
2. 与过敏覆盖层同时命中 → 警示 2 条、引用无重复锚点；
3. **零泄漏/白名单断言**：captured 模型请求体中不含特殊状态值；`aiCalls` 计数不变；
4. 开关关闭 → 行为与现状逐字一致（回滚验收）。

**E2E**：新增 `consult-special-status` 场景包（`x-test-scenario` 回放，与 `consult-allergy` 同范式），断言覆盖层零新增 LLM 调用 + 警示可见。

**回归**：`pnpm --filter @anxin/api test` 全量绿、`typecheck` 通过；既有过敏覆盖层/E2E fixture 字节不变。

## 5. 风险与待定

- **自由文本质量**：用户把「高血压」写进特殊状态 → 不命中（漏判，安全侧）。UI 可给建议值（PRD §7.1.2 入口一），不在本任务范围。
- **同义词表覆盖不足** → 漏判；表集中维护、随漏报/误报案例扩充，条目需人工复核（同「相互作用规则只能抄录」的纪律：不生成医学内容，只登记词形）。
- **与过敏警示重复**（用户既过敏又是孕妇）→ 最多 2 条，前端列表自然渲染，不合并（两类事实不同）。
- **植入器械类值**（起搏器）在药品说明书禁忌段罕见 → 多数情况不命中，属预期；不为它编造关联。
- **里程碑编号 / 排期待确认**：本文按 M15 建议；若并入其他里程碑，改标题与 commit 前缀即可。
