# G7 · 最小账号密码登录（过渡实现）

> 日期：2026-11-17
> 性质：关闭 [M12 上线差距盘点](./12-M12-上线差距盘点.md) §3 P1 · **G7 身份与访问**的工程侧；属受控模拟试点的前置工程项。
> 决策记录：[ADR #21](../07-技术选型决策记录.md)（鉴权过渡实现）；原定真实登录仍为 ADR #11（Better Auth + 手机号验证码，P1）。
> 范围：`app/` 代码 + `app/deploy` 运维配置 + 本文档；不引入任何外部账号/短信服务，不新增运行时依赖。

---

## 1. 目标与非目标

**目标（G7 关闭判据）**

1. 公网可达的 staging 不再「任意人直接拿到演示用户 p-001 的全部数据」：访问受保护接口必须持有有效会话 token；
2. 同一 token 只解析出所属用户，既有「所有仓储按 userId 过滤」的多用户边界在真实登录态下生效；
3. 默认方案不产生短信成本：账号密码登录（账号由管理员一次性下发）；
4. 既有 665 个 API 测试、fixtures E2E、本地 demo 开发零改动——由 `AUTH_MODE=demo` 旁路保证。

**非目标（本任务明确不做，留到后续）**

- 自助注册、自助改密、忘记密码自助找回（无短信/邮件通道；[[已知风险 §9]]）；
- 手机号验证码 / Better Auth（ADR #11 仍是 P1 目标）；
- 权限模型（患者/医生/管理员角色）与租户隔离——医生端仍按当前单一患者集合工作；
- HTTPS/TLS（属 G8 前收口；**接真实用户前必须完成**，见 §9 风险 1）；
- 多实例部署下的共享限流/会话撤销广播（当前 staging 单容器）。

## 2. 关键决策（与理由）

| # | 决策 | 理由 |
|---|---|---|
| D1 | **账号密码**，不用邀请码 | 邀请码本质是「一次性密码 + 分发/回收流程」，是一次性结构；账号密码的 `users` 凭据列 + `sessions` token 层可被 P1 手机号验证码登录直接复用（同一 session 表/同一 resolveUser 替换点）。已有 15 个 seed 用户，账号管理成本由 CLI 收敛。 |
| D2 | **密码只存 scrypt 哈希**（`node:crypto`，零新依赖），格式 `scrypt$N$r$p$salt$hash` | 避免引入 native 依赖（镜像构建是大陆链路敏感项）；每用户独立盐 + `timingSafeEqual` 比对。参数 N=16384/r=8/p=1。 |
| D3 | **会话 token 32 字节随机，DB 只存 SHA-256**；7 天固定过期；登出删行 | token 高熵无需慢哈希；即使 DB 泄漏也不能直接冒用 token；过期行在登录/解析时懒清理。 |
| D4 | **不做 HTTP 自助注册/找回**；账号由 CLI 开通、重置 | 演示规模（十余个账号），面向前台的自助流程没有价值且扩大攻击面；找回无通道。 |
| D5 | **登录失败限流：同一「IP+账号」5 次/15 分钟锁定**，单实例内存 | 限住公网爆破的最低成本实现；多实例前需换共享存储（已登记风险）。 |
| D6 | **`AUTH_MODE` 双模式：`demo`（默认）/ `password`** | demo 注入 p-001，保住 665 API 测试与 fixtures E2E 零改动；staging 用 password。compose 默认按 password **fail-closed**（旧 `.env` 没有该键也不会裸奔）；值非法直接 500，不静默退化。 |
| D7 | **401 统一语义**：缺 token=`AUTH_REQUIRED`、无效/过期=`AUTH_INVALID`、锁定=`AUTH_LOCKED`（429） | 前端只按 401 一处清登录态跳登录页；登录失败统一「账号或密码错误」不区分账号存在性（防枚举）。 |
| D8 | **token 存储**：web=localStorage、App=AsyncStorage（同键 `anxin-auth-token`） | 与现有平台接缝一致（core 注入 `AuthTokenStorage`）；cookie 方案对 RN 要另一套、且演示期 XSS 风险可接受（见 §9）。 |
| D9 | **手写过渡实现，不引 Better Auth** | 与 ADR #11 的偏差已记入 ADR #21：`resolveUser` 是 M1 起预留的唯一替换点，P1 换 Better Auth 时只替换该函数体；`users.username/password_hash` 列保留（登录时可重哈希迁移）。 |

## 3. 数据模型（迁移 `drizzle/0012_g7_auth_accounts.sql`）

**users 增列**（可空，兼容 demo 用户）：

| 列 | 类型 | 说明 |
|---|---|---|
| `username` | text unique | 登录账号（2–64 位字母/数字/._-）；null = 未开通登录 |
| `password_hash` | text | scrypt 哈希；null = 未开通 |
| `password_updated_at` | timestamp | 设密/重置留痕 |

**sessions 新表**：

| 列 | 说明 |
|---|---|
| `id` text pk | `sess-<uuid>`，应用生成 |
| `user_id` text not null | → users.id（应用层过滤，不设 DB 外键，与既有用户域一致） |
| `token_hash` text not null | sha256(token) hex，唯一索引 |
| `created_at` / `last_used_at` / `expires_at` | 7 天过期；解析时刷新 last_used_at |

索引：`sessions_token_hash_uq`（唯一）、`sessions_user_id_idx`、`sessions_expires_at_idx`。

## 4. API 契约（`shared/src/auth.ts` 一份真相）

| 方法/路径 | 鉴权 | 说明 |
|---|---|---|
| `POST /api/auth/login` | 匿名 | `{ username, password }` → `{ mode:'password', token, user:{id,name,username} }`；失败 401 `AUTH_INVALID`（统一文案）/ 429 `AUTH_LOCKED`；demo 模式 400 明确拒绝 |
| `POST /api/auth/logout` | Bearer（可缺） | 删除当前 session；幂等 200 |
| `GET /api/auth/me` | Bearer（demo 免） | 返回 `{ mode, user }`；前端启动 bootstrap 用；demo 返回 p-001 |
| 其余 `/api/*` | Bearer | 缺失 401 `AUTH_REQUIRED`；无效/过期 401 `AUTH_INVALID` |

错误码新增（`shared/src/errors.ts`）：`AUTH_REQUIRED` / `AUTH_INVALID` / `AUTH_LOCKED`。
响应体安全：对外用户对象只有 `id/name/username`，不返回 `password_hash/email/phone`。

## 5. resolveUser 双模式（唯一替换点）

```
AUTH_MODE=demo     → 读 p-001 注入（原行为逐字不变）
AUTH_MODE=password → Bearer token → sha256 → sessions（未过期）→ users → c.set('user')
```

- `/api/health` 与 `/api/auth/*` 注册在守卫之前；其余 `/api/*` 全部经守卫。
- 仓储层完全不变：既有所有查询已按 `c.get('user').id` 过滤，因此用户隔离是「解析变了、边界没变」。

## 6. 前端

**@anxin/core（web/App 共用逻辑）**

- `setAuthToken()`：所有 hc 请求自动带 `Authorization: Bearer`（与 `setExtraHeaders` 分开，避免 dev fixtures 头覆盖）；
- `setAuthTokenStorage()`：平台注入持久化（web=localStorage / App=AsyncStorage）；
- `useAuthStore`：`idle/loading/authenticated/anonymous/error` 状态机；
- `bootstrapAuth()`：启动恢复（demo 自动进 / 401 → anonymous / 网络失败 → error 可重试）；
- `signIn()` / `signOut()` / `resetAuthState()`；401 统一由各端 wiring 接到 `setUnauthorizedHandler`。

**web**：`/login` 登录页（适老化大表单 + 内联错误）+ `RequireAuth` 路由守卫（demo 模式直接放行）+ 设置页「账号」卡（当前用户 / 退出登录）。

**App（RN）**：`AuthGate` 包裹根 Stack（检查中 / 登录 / 出错重试 / 已登录四态，不新增路由结构）+ 设置页「账号」卡；token 走 AsyncStorage。根布局里的 `NotificationSync` 在 `status=authenticated` 之前不发 `/api/plans`、`/api/drugs`，避免 password 模式冷启动时「401 把刚恢复的登录态清掉」的竞态。

## 7. 运维（详见 `app/deploy/README.md` §6.6）

1. 本机走 SSH 隧道对部署库执行 `db:migrate`（runtime 镜像无 drizzle-kit）；
2. 服务器 `docker compose exec api node packages/api/dist/scripts/auth-create-user.js --username p-001 --id p-001 --name 张某某`（初始密码只显示一次）；
3. 重置：`auth-reset-password.js --username p-001`；
4. compose 默认 `AUTH_MODE=password`（fail-closed）；本地/测试缺省 demo；
5. 迁移完成后必须先建账号再对演示人开放（否则只有登录页、无账号可进）。

## 9. 已知风险与遗留（交付说明需抄录）

1. **明文 HTTP 传密码**：过渡期 `http://<IP>:8787`，登录密码与 token 在公网明文传输。当前只放演示账号 + 纯演示数据，**接真实用户前必须完成 HTTPS（§10）**；G8 前收口。
2. **无自助找回/改密**：忘记密码只能管理员 CLI 重置（无短信/邮件通道）。
3. **限流单实例内存**：多副本部署前要换共享存储（Redis/DB 计数）；进程重启清零可接受。
4. **会话不可批量撤销**：改密不会使既有 session 立即失效（7 天自然过期）；真实用户前需加「改密即清 session」。
5. **无角色/权限模型**：登录只解决「是谁」，不解决「能做什么」；医生端与患者端仍是同一账号体系。属 G7 之后的独立事项。
6. **XSS 风险**：web token 存 localStorage，演示期接受；接真实用户前可评估 httpOnly cookie 或 CSP 加固。
7. **与 ADR #11 的偏差**：手写实现是过渡态；换 Better Auth 时保留 `resolveUser` 替换点与 sessions 设计。
8. **断网时错误文案为技术英文**（真机实测）：`bootstrapAuth` 把原始异常 message 直接展示；G8 出包前在 core 做中文归类（web 同路径，随下次镜像更新）。
9. **release APK 目前用 debug keystore 签名**（Expo prebuild 默认）：G8 需正式 keystore + 可持久化的 expo config plugin（`android/` 不入 git）。
