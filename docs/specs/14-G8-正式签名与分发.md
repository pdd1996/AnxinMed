## 1. 目标与完成判据

**目标**

1. release APK 用**正式 keystore** 签名（不再用 Expo prebuild 默认 debug keystore），签名身份与证书指纹可核验；
2. 签名配置可持久化/可复现：`android/` 是 `expo prebuild` 生成物、不入 git，签名必须落在 **expo config plugin** 里，换机 prebuild 后自动生效；
3. 出包流水线 fail-closed：缺 keystore/凭据时拒绝出包，不允许静默打出 debug 签名包；构建后自动验签（证书 DN、ABI、包名、非 debuggable、SHA-256）；
4. 一次出包同时覆盖 **G8 签名** + **G7 §9.8 错误文案中文化**（同一个 APK 交付）；
5. 安装/升级/校验/内测分发有可执行说明；真机回归矩阵与证据模板（D1 已回填；≥3 ROM 归 T8 长期抽样）；
6. 密钥材料只在本机（`.credentials/`，gitignored），不进 git、不写进文档/命令示例。

**完成判据（逐条自验，证据见 §7）**

| # | 判据 |
|---|---|
| 1 | `with-release-signing` 插件注入 release signingConfig，release buildType 不再引用 debug 签名；dev/debug 构建行为不变 |
| 2 | keystore 生成脚本可复跑；证书 `CN=AnxinMed`，SHA-256 指纹与 `release-apk-info.json` 一致 |
| 3 | 缺凭据/缺 keystore 时 `pnpm --filter @anxin/mobile android:release` 以非 0 退出并给出中文操作指引 |
| 4 | 出包后 `apksigner verify --print-certs` 通过、签名者非 `Android Debug`、ABI 含 `arm64-v8a`、包名 `com.anxin.mobile`、非 debuggable |
| 5 | 同一 APK 内含 G8-B 中文错误归类（断网冷启动文案为中文） |
| 6 | 模拟器安装/登录/断网/重试冒烟通过（§6.2） |
| 7 | 真机验收：D1（OnePlus PJZ110 / ColorOS 15）P1–P13 实测并回填；**2026-11-18 用户裁定以 D1 通过即验收**（≥3 ROM 转为 T8 长期抽样，不阻塞 G8） |
| 8 | 既有回归全绿：API 688+ / Web / Core / Mobile；typecheck / lint 不退化 |

## 2. 关键决策（与理由）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 签名材料：PKCS12 keystore 放 `app/packages/mobile/.credentials/`（gitignored），密码随机生成后写入同目录 `release-signing.env` | `android/` 不入 git，`*.jks` 已被 gitignore；集中到 `.credentials/` 便于整目录备份/迁移。**keystore 丢失=无法覆盖升级**，必须离线备份（SIGNING.md §2）。 |
| D2 | 签名配置走 **expo config plugin**（`plugins/with-release-signing.js`，`withAppBuildGradle`），不手改 `android/` | 与 `with-release-hardening` 同一套理由：手改进不了版本库、prebuild 会抹掉。 |
| D3 | 凭据经 **Gradle project properties**（`ORG_GRADLE_PROJECT_ANXIN_RELEASE_*` 环境变量）传入，不写命令行、不写 `gradle.properties` | 复用 Gradle daemon 时 `System.getenv` 可能是旧环境（T8 已踩过）；`-P` 会进进程列表；`ORG_GRADLE_PROJECT_*` 由 Gradle 客户端转成 project properties，可靠且不落盘。 |
| D4 | release 构建**缺凭据即失败**（GradleException，中文指引） | 禁止「看起来出了包、其实 debug 签名」；debug 构建不受影响。 |
| D5 | 出包脚本构建后**自动验签**并归档到 `dist/release/`（APK 副本 + `release-apk-info.json`） | 手抄 SHA-256 会错；证据与产物同目录，便于分发核对。 |
| D6 | 分发：不上商店，走**内测直发 APK**（adb / 文件传输 / 内网分发页），按账号清单受控发放 | M5 任务书口径：真实模拟阶段不上商店；G4 合规未完成前也不具备公开分发条件。 |
| D7 | 升级规则：G7 的 debug 签名包与正式签名**不能覆盖升级**，必须卸载重装 | Android 签名校验的硬约束；演示数据在服务端，卸载只清本地 token/设置，可接受。 |
| D8 | 过渡期仍指向 `http://<staging-IP>:8787`（cleartext） | 域名/备案是外部依赖；只在演示账号 + 纯演示数据下受控使用。**接真实用户前必须 HTTPS**（§8）。 |

## 4. 操作手册（构建机）

### 4.1 首次：生成正式 keystore（只做一次，然后离线备份）

```powershell
cd app
node packages/mobile/scripts/gen-release-keystore.mjs
# 输出：.credentials/anxin-release.p12 + .credentials/release-signing.env + 证书 SHA-256 指纹
# ⚠ 立刻把 .credentials/ 整目录复制到离线介质（至少两处）；丢失后新包无法覆盖升级，只能换包名/让用户重装
```

> `.credentials/` 已被 gitignore；**不要**把密码贴进 issue/文档/聊天。

### 4.2 出包

```powershell
cd app
pnpm --filter @anxin/mobile android:release
# → android/app/build/outputs/apk/release/app-release.apk
# → dist/release/anxin-<版本>-<commit>.apk + release-apk-info.json（SHA-256/证书/构建时间/API 地址）
```

前置：
- `app/packages/mobile/.env.production.local` 或 shell 的 `EXPO_PUBLIC_API_URL` 指向可访问的后端（当前 staging：`http://118.196.82.13:8787`）；
- 首次/prebuild 后构建需 Gradle 依赖（本机代理见 `README.md`「本机工具链与构建环境」）；
- `android/` 由 `expo prebuild` 生成：**换机或 `prebuild --clean` 后插件自动重新注入**，无需手改。

### 4.3 验签（可对收到的任意 APK 复跑）

```powershell
cd app
node packages/mobile/scripts/verify-release-apk.mjs packages/mobile/dist/release/<APK>
# 通过：exit 0；证书 CN=AnxinMed；非 Android Debug；arm64-v8a；非 debuggable
Get-FileHash packages/mobile/dist/release/<APK> -Algorithm SHA256   # 与分发页 SHA-256 比对
```

### 4.4 安装

```powershell
# adb（推荐，可取证）
adb install -r packages/mobile/dist/release/<APK>

# 从 G7 debug 签名包迁移：必须先卸载（签名不同，覆盖安装会 INSTALL_FAILED_UPDATE_INCOMPATIBLE）
adb uninstall com.anxin.mobile
adb install packages/mobile/dist/release/<APK>
```

文件传输安装（微信/QQ/网盘/U 盘）：手机端允许「安装未知应用」后点开 APK。部分 IM 拦截 `.apk`，可压缩后传。

## 8. 已知风险与遗留（交付说明需抄录）

1. **key 丢失不可升级**：keystore 是唯一签名身份，丢失后新包无法覆盖旧包，只能卸载重装（用户本地数据清空）。必须离线双备份，口令单独保管。
2. **过渡期明文 HTTP**：`http://<IP>:8787` 下登录密码/token 公网明文传输，仅限演示账号 + 纯演示数据；**接真实用户前必须 HTTPS**（域名 + ICP 备案 + Caddy 自动证书，见 `deploy/README.md` §10；域名/备案是外部依赖）。
3. **无崩溃上报/遥测（端上）**：客户端崩溃仅靠 logcat/用户反馈；服务端错误落盘归 G10。
4. **无自动更新**：新版本需手工重新分发 APK；版本号规则见 SIGNING.md。
5. **真机覆盖仅 1 台（用户裁定接受）**：D1（OnePlus PJZ110 / ColorOS 15）已跑 12/13 项，2026-11-18 用户裁定以此验收 G8；其他国产 ROM 的兼容性与提醒准时率仍属未知面，归 T8 专项长期抽样——新增机型不复核旧结论。
6. **签名轮换**：如确需换 keystore（丢失/交接），应升包名或保留旧包升级链，并按 §5 通知所有试点用户；不得静默换签。
