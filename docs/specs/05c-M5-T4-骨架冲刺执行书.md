## 前置条件（开工前逐条核实，不满足即停）

1. **T2 已落地**：`app/packages/core` 存在且 `pnpm -r typecheck && pnpm test` 全绿——本任务复用 core 的 intake 决策函数与 `@anxin/core` 的 API client（含 ApiNotifier 注入口）；
2. 真机就绪：T3 已验收（OPPO PJZ110 / Android 15，无线 adb 可用；`adb pair` 流程见 T3 交付记录）；
3. 本机 dev API 可跑（`pnpm --filter @anxin/api dev`，端口 8787；手机与电脑同 Wi-Fi）。

## 任务范围（**最细一条线**，宽度留 T6/T5）

1. **拍照**：`expo-image-picker` 调相机（`implementation` 用原生相机，**禁用裁剪/编辑**——用户拍什么传什么）；JPEG `quality` 参数对齐 OCR 预检要求（参考 web 端 `lib/intake.ts` 的质量口径与 `app/packages/api` 预检阈值，选 0.8 起步并在交付说明记录依据）；权限拒绝时的引导文案。
2. **上传与检测**：POST `/api/intake/detect`（用 core 的 client，禁硬编码 URL——`EXPO_PUBLIC_API_URL` 环境化已就绪，`.env.local` 指向电脑局域网 IP）。请求超时与进度态必须有 UI 反馈。
3. **质量预检**：**mobile 一期可不做**（05 任务书 T2/T4 明确允许降级——「建议不拦用户」，core 的 `ImageStatsProvider` 接口已留位，二期再补实现）；一期仅做 core 的 `validateFile`（结构化形状，picker asset 天然兼容）+ 服务端返回的质量结果展示。
4. **确认**：层检测结果确认页（检测结果 + 用户可理解文案；复用 core 的 `mapIntakeFailure` 与文案常量，**禁静默吞错**——断网 / HTTP 500 / OCR `PARSE_FAILED` 三种失败各有明确反馈）。
5. **入箱**：确认后走 core 的入库流程 → 药箱列表渲染（本任务只做列表最简渲染，完整五页是 T5）。

**明确不做**（做即返工）：处方笺+药盒双入口完整化（T6）、从药盒/标签抄录用法用量（PRD V2.1 已删）、五页全量移植（T5）、提醒（T8）。

## 联调口径

- dev 阶段 `.env.local` 指向电脑局域网 `192.168.124.8:8787`（现值即此）；release 复验连火山等 T1——**第一周判定不被 T1 绑架**（05 任务书 T4 第 3 条）；
- 手机与电脑需同 Wi-Fi；Windows 防火墙若拦 8787 入站，加一条入站规则放行 TCP 8787（限专用网络）——此为环境操作，失败如实记录。
