# 27 · 说明书资料卡与分段页（P0/P1/P2 收口）

> 2026-11-20。状态：**已实现（web + mobile + api + 数据脚本）**；staging 需按 §7 部署与执行数据脚本。
> 触发：用户截图反馈「问磷酸奥司他韦说明书有吗」的回答是一堵 1000+ 字未核验原文墙，
> 且「未核验/来源」提示在卡片最底部。按评审建议落 P0/P1/P2 全部条目。

## 1. 背景与目标

L0（manual 档 / 说明书未核验）走确定性原文拼装，`precautions` 常为「单元素整段」（可达 1000+ 字），
旧版把整段塞进 `keyPoints`、`l0Notice`/citations 放在卡片底部 → 首屏看不到未核验状态、文字不可读、
用户问「有没有说明书」却得到适应症原文。

目标：**不生成、不改写医学内容**，只做展示层的短摘要/折叠 + 独立分段落页；
同时把数据层的长段落整理成逐条数组（仅 crawled 行）。

> 2026-11-20 用户裁定（两次）：① 咨询卡**不渲染顶部未核验 banner**（截图反馈「这个删除」）；未核验状态/身份/
> 来源/批准文号只在「查看完整说明书」分段落页展示，咨询回答的 summary 里保留「已人工核验/尚未人工核验」一句；
> `l0Notice`/citations 后端契约与留痕不变。② **「说明书可用性」专用回答整卡不要**（截图反馈「这个也不要了」）——
> 该意图已移除，问「说明书有吗」回到原 S1 说明书管线（L0 原文卡 / LLM 摘要，取决于核验状态）。

## 2. 回答结构（L0 / 降级路径，`services/consult/sections.ts`）

- `fallbackSectionsFromInsert`：
  - summary：所选段落 → 去长括注（≥10 字）、去句首编号、合并 PDF 折行空格、截前 90 字整句；
  - keyPoints：注意事项按行首编号拆条 → 前 3 条、每条 ≤64 字整句；
  - risks：禁忌前 2 条、每条 ≤50 字；
  - nextAction：命中严重警示词（致命/精神神经/谵妄/惊厥/幻觉/行为异常/严重过敏/呼吸困难）→
    「如出现…请立即就医」固定安全语；否则「具体是否适用、用法用量及疗程请咨询医生或药师。」
  - details：所选段落全文 + 注意事项逐条原文（前端「展开原文（N 条）」）。
- 不调 LLM、不改写医学内容；原文始终可在展开区逐字核对。

## 3. 引用与核验状态

- `shared/CitationSchema` 增可选 `reviewStatus`（`mock|crawled|reviewed`）、`specification`、`approvalNumbers`；
- `insertCitation()` 从 `InsertSlice` 自动填充（本地说明书引用也标核验状态，不再只有 `unverified` 一个布尔）；
- 来源卡（web/mobile `CitationsList`）：`unverified` → 「未经本库核实」；
  `reviewStatus !== 'reviewed'` → 「说明书未经人工核验」；并展示规格/批准文号。

## 4. 说明书可用性意图（已移除，2026-11-20 用户裁定）

- 原实现：`services/consult/availability.ts` + S1 已绑定药分支，命中「说明书 + 有吗/能看…」时给 0 LLM 的
  「已收录/未核验/未收录 + 来源/版本/批准文号 + 查看入口」专用卡。
- **现状：整块移除**（`availability.ts` 删除、service 钩子删除、trace 层 `leaflet` 枚举删除、测试改为回归断言
  「说明书有吗不再走可用性卡、回到 S1」）。用户截图反馈该卡不需要。
- 保留：`ConsultResponseSchema.leafletDrugId`（L0 资料卡/普通回答仍带「查看完整说明书」入口）、
  citation `reviewStatus` 与分段落页；问句本身回到原有 S1 路由。

> 注：`fallbackSectionsFromInsert` 的 summary 仍会是「已收录/未核验」语义之外的原文摘要；是否给「已收录」类
> 元信息由产品另行裁定，不在本 spec 范围。

## 5. 分段落页

- API：`GET /api/drugs/:id/leaflet`（`services/leaflet.service.ts` + `routes/drugs.ts`）：
  - userId 隔离；未收录/越权统一 404（不泄漏存在性）；
  - 分段顺序固定（适应症/用法用量/禁忌/注意事项/不良反应/特殊人群/相互作用/药理/药代/过量/性状/成份/规格/批号/贮藏/效期/包装/生产企业/执行标准）；
  - **用法用量段恒为「医嘱范畴」固定提示**（不含任何剂量数字）；
  - 未核验 → `reviewed=false` + `notice`；已核验 → `notice=null`。
- 前端：
  - web `/leaflet/:drugId`（`routes/patient/Leaflet.tsx`，懒加载路由）；
  - mobile `app/leaflet/[drugId].tsx`（根 Stack，标题「说明书」；expo typed routes 已重生成）；
  - 默认展开「适应症/禁忌」，其余按需展开；未核验顶部固定 banner。
- 入口：咨询回答卡 `leafletDrugId` → 「查看完整说明书」；web 用 `<Link>`、mobile 用 `router.push`。

## 6. 数据整理（仅 crawled 行）

- 脚本：`app/packages/api/src/db/oneoff-2026-11-20-normalize-crawled-inserts.ts`
  （`pnpm --filter @anxin/api db:normalize-crawled-inserts`）。
- 内容：注意事项/禁忌单元素整段按行首编号拆条 + typed 长文本 PDF 折行空格归一；
  **不改 curationStatus**（未核验不能借清洗升格）；reviewed/mock 行不碰；sourceSections 不动（展示时实时归一）。
- 安全：默认 dry-run；`--apply` 需 48h 内 pg_dump；单事务；逐行字符完整性校验（忽略空白逐字相等）；
  事务内幂等校验。本地 dev 库执行结果：**crawled 1393 行 → 整理 1380 行**
  （注意事项拆条 1303 / 禁忌拆条 774 / 仅 typed 折行 66），再跑 0 变更。
