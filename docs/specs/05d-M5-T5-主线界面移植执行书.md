**做什么**

2. OnboardingGate 等价物：web 的守卫不跳转，是**全屏声明卡覆盖整个 RouterProvider**（`web/src/components/OnboardingGate.tsx:12` 键 `anxin-onboarded`、`:21` 读 `localStorage==='1'`、`:49` 写 `'1'`）→ mobile 换 AsyncStorage 同键、声明卡文案逐字照搬，禁止新写一套话术。
3. **字号全局缩放（本片最大不确定项）——spike 已定案：方案③ NativeWind 运行时 rem 根**（2026-09-30 用户拍板）。
   web 靠 `document.documentElement.dataset.scale` 驱动 rem（`components/layout/FontScaleSync.tsx:11`），`web/src/styles/index.css:112,116` 定 `html{font-size:17px}` / `html[data-scale='large']{font-size:20px}`。RN 侧 NativeWind v4 **本就有同一个旋钮**，只是默认被编译期烤死：
   - `react-native-css-interop/src/runtime/native/unit-observables.ts:9` `export const rem = observable(14)`，同包 `styles.ts:197-198` 注册 CSS 时执行 `rem.set(data.rem)`——**rem 是运行时可观察量，set 之后所有订阅它的元素重解析**（与 dark mode 的 `colorScheme` 同一条通道）；
   - 但 `src/css-to-rn/parseDeclaration.ts:1840-1852` 的 `inlineRem` 默认是**数字 14**，数字即编译期 `value * inlineRem` 烤成常数；`nativewind/dist/metro/index.js:14` 的 `withNativeWind(config, { inlineRem = 14 })` 就是这个默认值的出处。**故必须显式传 `inlineRem: false`**，否则 `rem.set()` 打不动已烤死的类。
   - 落地三处：`metro.config.js` 传 `inlineRem: false`；`src/global.css` 的 `:root` 加 `font-size: 17px`（`css-to-rn/index.ts:452-461` 会把它读成运行时 rem 初值，注意此时 `inlineRem` 必须已是 `false`，否则反过来被它当内联值）；`src/components/FontScaleSync.tsx` 订阅 core 的字号 store 执行 `rem.set(17|20)`。
   - **代价与影响面**：`inlineRem` 从 14 改 17 后，现有四页（index/intake/box/drafts）所有 rem 基准的文字与间距整体放大约 21%（14→17），必须在真机逐页复查溢出与截断——这是 §6 第 2 条与第 17 条的实测内容，不是回归缺陷。写死 px 的触控目标（`min-h-[44px]` 一族）不随 rem 变，符合 §6 第 1 条口径。
   - 未选的两条：① 逐组件切基类只缩放文字、间距不跟，与 web 语义不等价，还要长期守「禁裸 Text」；② RN 0.86 无 `textScaleMultiplier`（`node_modules/react-native` 全仓 grep 零命中），`allowFontScaling` 跟的是**系统** fontScale，与应用内两档不是一回事。
   - §6 第 2 条判据（normal=根 17 / large=根 20 等比）按方案③原样成立，不改。
4. QueryClient 装配在 `_layout`，`staleTime: 30_000`（对齐 `web/src/App.tsx:11`）。

**完成标准**：五 tab 可导航且样式互不串；字号两档在真机各页均生效、长文案不截断；杀进程重开字号保持；`typecheck`/`lint` 绿。
