## T1. AI 咨询服务（`src/services/consult/`）

**做什么** 迁移 `demo/server/index.js` `/api/consult`（940–1410 行，守门逻辑已实测）为 TS，并按 PRD §7.5 强化：

1. **按键取数**（不用 RAG）：咨询对象为已确认药品 → `packageInserts` 按 `drugId` 直查；按问题类型取对应段落（适应症/用法用量/不良反应/药理毒理/相互作用…），结构化取数优先；
2. **上下文组装**：本地说明书资料 + 白名单用户信息（健康信息视为"用户提供的、未经医学验证"）+ 相互作用提示（规则库按生效计划集合匹配后随提问注入）；
3. **安全守门 L1–L4**（照搬 demo 实测逻辑并保持可测）：
   - L4 紧急信号（胸痛/急救词）：停止常规流程 → 引导急救，触发留痕；
   - L3 拒答：停药/换药/剂量调整类问题 → 拒答 + 引导开方医生；
   - L2 剂量过滤：`stripDosageAdvice`（回答中具体剂量/频次数字被过滤，附固定提示语）；
   - L1 正常回答：citations 必含 药名 + source + version（说明书来源三件套）；
4. **确认状态三档门禁**：`manual` 档药品仅可 L0 资料查询（说明书解释），不可进入个体化用药解释（接口层拒绝并说明原因）；
5. **医疗搜索默认关**：本地未命中该药品时才兜底开 Baichuan 医疗搜索，回答必带"基于网络检索，未经本库核实"标注，且只做一般性资料解释（env 开关 `ENABLE_MEDICAL_SEARCH`，默认 false）；
6. `POST /api/consult`：请求 `{ question, drugIds[] }` → 响应 `{ answer, citations[], riskLevel, notice?, blocked? }`。

**完成标准**：守门单测 ≥ 12 case（L4 各口语变体、L3 停药变体、L2 数字过滤、manual 档门禁、本地未命中兜底标注）；集成测试一条完整 L1 回答含合法 citations；AI 不可用 → `AI_UNAVAILABLE` 且不影响其他功能。

## T3. 医生端洞察 Agent（`src/services/insight/`）—— 读库版

**做什么** 把 `demo/doctor.tsx` + `demo/server/index.js` insight 两接口迁到新栈，**数据源从 mock JSON 改读 PostgreSQL**：

1. 5 个只读工具落库版：患者列表（users + health_profiles + 生效计划数）、依从性统计（records 聚合，PG 原生 SQL `count(*) filter`）、风险事件流（L4/L3 触发留痕表——新增 `risk_events` 表：`id/userId/date/level/type/detail/createdAt`，M1-T9 若已 seed 静态数据则迁表）、咨询历史摘要（consult 留痕，新表 `consult_logs`：`id/userId/question/riskLevel/blockedAt`）、最近用药集合（plans+drugs）；
2. `GET /api/insight/patients`：患者列表 + 概要（迁移 demo 1297 行起逻辑，统计改 SQL）；
3. `POST /api/insight/summary`：选定患者 → 组装上述五类数据 → Baichuan 生成摘要 → 输出带数据引用的洞察文本（参照 demo 1313 行起 prompt 结构）；
4. 前端 `/doctor/insight`：迁移 `demo/doctor.tsx`（独立分支、无底部导航），患者卡 + 摘要生成/展示；风险事件 L4/L3 标红橙。

**完成标准**：与 mock 数据等价的 seed 入库后，医生端三屏（列表/详情/摘要）数据来自 DB（可断开 mock JSON 验证）；摘要生成有单测（数据组装部分，LLM mock）；演示患者 p-001 数据正确显示。

## T7. 医生端队列 Agent——依从性统计、分类与图表（增补）

> **增补任务（2026-09-07）**：PRD V2 无医生端条目（医生端属 ADR #12「演示价值保留」），本任务为演示增强，**不阻塞 `m3-done`**；选型依据 ADR #17（语义化只读查询工具 + 固定图表模板，禁 text-to-SQL）。

**做什么** 在 T3 读库版洞察之上，支持「病人过多」的队列级问法（统计依从性差的患者数、按分档分类、图表）：

1. **多患者 seed**：seed-demo 由单用户扩为多患者（≥8 位，依从性分档各异：优/中/差 + 漏服时段模式差异），供队列视图演示；
2. **聚合查询改造**：`listPatientsWithStats` 现为逐用户循环查库（N+1）——改为 repo 层聚合 SQL（依从性分档统计并入列表查询，PG `count(*) filter` 方言沿用 T3 口径）；分档阈值（如执行率 <80% 为差）落 `@anxin/shared` 契约，前后端一份真相；
3. **语义查询工具注册表**（沿用 consult/dataquery 模式）：工具 = zod 参数 schema + repo 只读函数 + 结果契约 + 图表模板绑定。首批三个：`adherence_distribution`（依从性分布）、`patient_cohort`（按分档/时间窗过滤队列）、`risk_event_rollup`（L4/L3 事件流聚合）；工具 zod schema 导出 JSON Schema 供 DashScope `tools` 参数；
4. **意图路由两级**：正则白名单主路径（固定问法 0 次 LLM 直查；新增关键词必须先在单测里补口语变体，intent.ts 同款纪律）；漏判长尾走 Qwen function calling 兜底——`tool_call` 参数过 `safeParse` 才执行，校验失败错误可见（禁止静默吞错）；
5. **图表**：固定模板三件（分档分布直方图、队列表格、事件时间线）由前端按结果契约渲染；仅 ad-hoc 问法走 Qwen 生成 ECharts 配置 JSON（zod 校验子集），后端不生成图片；
6. **叙述摘要**：百川出队列/患者摘要（insightSummary 既有模式），数字全部来自工具计算结果，过 `guardSummary` 二次守门；LLM context 字段最小化（统计 + 必要字段，不带全量身份信息）；
7. **前端 `/doctor/insight` 扩展**：队列视图（分档统计卡 + 图表 + 患者下钻为显式动作）。

**完成标准**：

- 固定问法 ≥6 条 golden（分布/差档队列/事件聚合各 2）**0 次 LLM 调用**直查库（E2E 红线断言，同 consult-dataquery 口径）；
- Qwen 兜底路径（mock 注入）：`tool_call` 参数非法 → 拒绝执行且错误可见；全链路无写 SQL 可达路径；
- 分档阈值边界值单测（shared 契约），前后端展示口径一致；
- 图表三模板组件测试或截图存档；队列页断开 mock 后数据来自 DB；
- 多患者 seed 下 `GET /api/insight/patients` 返回全体患者，聚合查询无 N+1（SQL 日志或耗时断言）。
