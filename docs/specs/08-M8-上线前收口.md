## §0 目标与边界

**目标**（三条线，按「先立规矩 → 再补内容 → 最后开闸」顺序）：

1. **相互作用规则库正式化**：从「3 条演示抄录、来源不可校验」变成「有来源分级、逐字可校验、可审计、UI 不再冒充正式」的库；
2. **reviewed 扩面**：把 **demo 路径**（p-001 药箱 5 药 + DXY 15 行）推进到 reviewed，并留下可复用的扩面队列与预检工具；
3. **上线闸门**：给出可复算的覆盖指标、已知限制清单、验收回归结果，以及「模拟可用 / 公开发布不可」的分档结论。

**本里程碑明确不做**（做即返工）：

- **不生成任何规则内容**。没有合格来源的组合**不建规则**（PRD §7.8.1 来源限定：两药说明书的相互作用段、药监局修订公告、权威指南共识）；
- **不用「注意事项」段顶替「相互作用」段**，也不把改写/摘要句当抄录——现有 3 条演示规则的来源问题如实登记，不洗白；
- **不批量刷 reviewed**。本轮只做 demo 路径 15 行 + 扩面队列；全库批量升格另开任务，且必须有真实人工核对能力；
- 不改咨询 Agent 的 prompt / 取数策略 / 守门规则；不改 `web` 患者端 UI（H5 冻结，AGENTS.md 与 05 §0）；移动端只做「状态标识」这一处最小改动；
- 不引入付费/授权数据源（无授权，登记为**公开发布阻塞项**）；
- 不改药品身份模型（规则仍按 `drug_master.id` 精确集合匹配；跨规格/跨商品名归并列为已知限制，不在本里程碑）。

**决策记录**（本任务书立项时定，后续不再反复）：

| # | 决策 | 理由 |
|---|---|---|
| D1 | **规则库本里程碑以「可验证」为目标，不以条数为目标**；现有 3 条保留但降为 `status='demo'`，UI 明示；能逐字校验且来源合格的组合才可 `curated` | 立项核对发现：3 条 note 在对应说明书中**均非逐字子串**；`ir-002`/`ir-003` 来源是注意事项段，不在 PRD §7.8.1 允许来源内。把演示条目洗成「正式」比没有规则更危险 |
| D2 | **reviewed 扩面先做 demo 路径（15 行 DXY），不做全库批量** | reviewed 是 L1 咨询门禁；现有 230 行由 `Robot-校准` 批量升格，属历史口径。本轮不扩大自动升格，先把 demo 路径做成可核对、可审计的样板 |
| D3 | **上线闸门分两档**：`模拟可用`（demo 范围、规则/说明书均显式标注演示与覆盖限制）与 `公开发布不可`（规则库缺授权来源、说明书数据授权与医疗/法律确认未完成，PRD §14） | 不把「demo 能跑」包装成「可上线」 |

**人工闸门**（必须留痕，不得由代理代签）：

- `curated` 规则入库前：逐字 quote + 来源引用 + 核对人签名（`reviewed_by`）；
- DXY 15 行升 reviewed 前：自动核验报告 + 人工抽检 ≥5 行；`reviewed_by` 记实际执行者/口径，不得写成不存在的真人；
- 公开发布结论：只出「阻塞项清单」，不由代理给出可发布结论。

## T1. 规则库正式化：数据模型与守门（工程可闭环）

**做什么**

1. **schema 增列**（`interaction_rules`，drizzle 迁移进 git）：
   - `status` `varchar enum('demo','curated','retired') not null default 'demo'`；
   - `source_type` `varchar enum('manual-interaction','nmpa-announcement','guideline') null`；
   - `source_ref` `text null`——建议 JSON 串：`{insertId, drugId, sectionKey, version, url?}`；
   - `quote` `text null`——逐字抄录的原文；
   - `reviewed_by` `text null` / `reviewed_at` `timestamp null`。
   - 存量 3 行迁移为 `status='demo'`、`source_type=NULL`。
2. **纯函数守门** `src/services/rules/rule-curation.ts`：
   - 规范化：全半角/空白归一，用于子串比较；
   - `note` 必须是 `quote` 的规范化子串；`quote` 必须是所引用说明书段落（`sourceSections[sectionKey]`）的规范化子串；
   - `source_type='manual-interaction'` 时 `sectionKey` 只允许「药物相互作用」及已知变体；
   - `status='curated'` 时：`quote`/`source_ref`/`reviewed_by` 必填，且所引说明书行必须 `curation_status='reviewed'`；
   - `drugIds` 每个都存在、去重后 ≥2、规则间药物集合不得完全重复（同对只留一条，除非分级不同且 note 不同——需显式 allowlist）；
   - `level` 四枚举校验复用 shared；所有失败返回错误码 + 中文信息，不静默。
3. **seed 脚本 v2**：读取 `seed-interaction-rules.json`（结构升 v2），入库前逐条过守门；`--check` 只校验不写库；幂等 upsert 保留。
4. **API/类型**：`InteractionRuleInput` / `InteractionHit` 增 `status`；`assets.repo` 映射；`checkInteractions` 命中透传 `status`；`data-audit` 以 `status` 优先判定真实/演示（旧 source 兜底）。
5. **移动端最小标识**：命中卡对 `status='demo'` 显示「演示抄录 · 非正式规则库」徽章；`curated` 不显示。**不改 consulting context 文案**（`INTERACTION_COVERAGE_NOTE` 同时进入 LLM prompt 回放 fixture，改动会使逐字节 fixture 失效——演示标注由 UI 徽章承担）。
6. **测试**：守门纯函数 ≥12 case（逐字/非逐字、来源段不符、未 reviewed、重复对、非法 level、demo 放行、curated 缺字段）；seed `--check` 集成 1 条；`checkInteractions` 透传 status。

**完成标准**

- 迁移可 `db:migrate` 且幂等；存量 3 行 `status='demo'`；
- `db:seed-interaction-rules --check` 对现有 JSON 通过；构造非法样本逐条报错（测试覆盖）；
- `pnpm --filter @anxin/api test`、`pnpm -r typecheck`、`pnpm lint` 全绿；
- 移动端徽章有组件测试（demo 显示 / curated 不显示）。

## T3. reviewed 扩面：DXY 15 行（demo 路径）

**做什么**

1. **回填**：从 `data/crawled/*.json` 把 `sections` 写回 15 行的 `source_sections`，并按 `fallbackContentHash(sections)` 回填 `content_hash`；写 `curation_note` 注明「M8 回填，来源=爬虫草稿」；dry-run → apply，单事务；
2. **扩展导出**：`db:review-export` 支持 `--source dxy`（以 `source_url` 为来源标识、不要求 `sourceFile`）；导出 15 行 + 草稿全文 + 来源 URL；
3. **自动核验脚本** `src/scripts/review-dxy-check.ts`（或纯函数 + CLI）：
   - 身份：`genericName/brandName/specification` 与草稿一致；
   - 六必核段：有正文 → `verified`；无正文且草稿确实无该段 → `source-missing`；有正文但映射列为空或与 sections 不一致 → 报错；

4. **人工抽检**：15 行全量过脚本后，抽 ≥5 行对照 DXY 来源 URL/草稿原文，判定 pass/suspect；suspect 不进 reviewed；

**完成标准**

| 相互作用段可得率 | 有非空【药物相互作用】段的行 / 总行（PDF/DXY 分列） | DB |
| L0 原因分布 | `manual` / `unverified` / `no-source` 各自计数 | 咨询守门单测 + SQL 统计 |
