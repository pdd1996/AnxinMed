## §1 根 compose 加 caddy（不建平行 prod compose）

现状：`app/docker-compose.yml` 本就是生产形态（api 多阶段镜像 + postgres:18-alpine）。在此文件上加第三个服务：

- 服务名 `caddy`，镜像 `caddy:2-alpine`，ports `80:80` `443:443`（备案下来才用得上，先占位）；
- 挂载 `./deploy/Caddyfile:/etc/caddy/Caddyfile:ro` 与 `caddy_data`/`caddy_config` 两个 volume；
- `depends_on: [api]`；api 服务**保持 8787 直出**（ports 已有则不动）；
- **postgres 的 5432 端口改为 `127.0.0.1:5432:5432` 绑定或去掉映射**（数据库不进公网——05 任务书 T1 第 2 条硬要求）；
- 布局原则：docker-compose 与各服务 Dockerfile 是既有生产形态，只加不改。

## §2 `app/deploy/` 目录（全部入库；真实 .env 不入）

1. `app/deploy/Caddyfile`——**过渡期版本**：只放一条注释骨架（备案后启用），当前公网入口是裸 IP `http://IP:8787` 直连 api，Caddy 暂不承担流量。附 `Caddyfile.https.example`：备案后 `域名:443` 反代 `api:8787` 的模板（`reverse_proxy api:8787`）。
2. `app/deploy/.env.example`——服务器 `.env` 模板：`DATABASE_URL`（compose 内 db 服务名）、`POSTGRES_PASSWORD` 占位、`DASHSCOPE_API_KEY` 占位（LLM key 只存在于服务器 .env——05 任务书 T1 第 6 条）、`AI_MODE` 等 api 侧所需变量，逐项带注释；**不含任何真实值**。
3. `app/deploy/backup.sh`——`pg_dump` 每日备份脚本（docker exec 进 db 容器 dump 到挂载目录，保留最近 N 份轮转），供服务器 cron 调用；可执行位。
4. `app/deploy/README.md`——运维清单（Qoder 写，用户照做）：服务器装 docker → 传 `.env` → `docker compose up -d` → 数据迁移逐条命令（`docker compose exec api pnpm db:migrate`、`db:seed`、`db:seed-interaction-rules`，mock 阶段重建成本≈0，优先重建而非 pg_dump 恢复）→ 安全组表格（22 限源 IP / 80·443 / 8787 过渡期直出）→ **勿把服务改到 80 端口**（未备案域名解析大陆 IP 时 80/443 被云厂商拦）→ 域名持有者须与备案主体一致 → 备案下来后：换 Caddyfile HTTPS 版、APK 改 `EXPO_PUBLIC_API_URL` 重打包、关闭 cleartext（改 `app/packages/mobile/app.json` 的 `usesCleartextTraffic: false`）→ 快照每日 + `backup.sh` cron 每日 + UptimeRobot 监控 `http://IP:8787/api/health`。
