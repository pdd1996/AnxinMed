## 1. 目的与边界

回答一个数据问题：**规则路由已有 100% 评测基线的情况下，小模型分类器是否值得接线上？**

- 只做离线对照，**不修改任何线上路由**；
- 输入只给「脱敏问题 + 意图枚举」，输出 zod 校验；temperature=0、非思考；
- 评测语料 = `consult-intent-eval.json` 中自由文本路由用例（期望 S1 / S2*，共 96 条；S0 守门与 P1 clarify/out-of-scope 不参与意图分类）；
- 指标重点看**危险方向**（期望 S1 却判 S2 —— 会把该解释的问题错误路由到数据模板）与**安全漏判**（S2→S1，可通过规则兜底）。

## 2. 方法

| 项 | 内容 |
|---|---|
| 脚本 | `api/src/scripts/eval-consult-intent-classifier.ts` |
| 模型 | `qwen3.8-flash`（`enable_thinking=false`）/ `deepseek-flash`（`thinking:{type:'disabled'}`），temperature=0，JSON 输出 |
| Prompt | 6 类意图（S1 + 5 个 S2），规则「宁走 S1、不确定选 S1、只输出 JSON」 |

| 产物 | `app/backups/intent-classifier/report-2026-11-18-*.json/.md`（gitignored） |

运行命令：

```bash
cd app/packages/api
pnpm exec tsx src/scripts/eval-consult-intent-classifier.ts --concurrency=4 --refresh
```

## 3. 结果（2026-11-18）

| 模型 | 准确率 | S1（39 条） | 5 个 S2（49 条） | 危险方向（S1→S2） | 安全漏判（S2→S1） | P50 / P95 |
|---|---|---|---|---|---|---|
| 规则基线（线上） | **100%** | 39/39 | 49/49 | 0 | 0 | — |
| qwen3.8-flash 非思考 | 90.6%（87/96） | 30/39 | **49/49** | **9** | 0 | 537ms / 984ms |
| deepseek-flash 非思考 | 93.8%（90/96） | 33/39 | **49/49** | **6** | 0 | 686ms / 1070ms |

**危险方向样本**（两模型共性）：都是「解释/行动类」S1 题被误判为数据查询，例如：

- 「漏服了怎么办」→ 误判 `S2/adherence`
- 「漏服一次要补吗」→ 误判 `S2/adherence`
- 「这瓶药过期了还能用吗」→ 误判 `S2/expiry-stock`
- 「这个药快过期了还能吃吗」→ 误判 `S2/expiry-stock`
- 「我的药一起吃有相互作用吗」→ 误判 `S2/interaction-check`
- 「这个药和他汀一起吃有风险吗」→ 误判 `S2/interaction-check`

即：模型能学会「**问了什么数据**」，但学不会规则层「**问的是能不能/怎么办 → 走解释**」的仲裁语义。S2 侧全对说明召回不缺，缺的恰恰是安全方向。

## 4. 结论

**不接线上。** 依据（与 docs/14 T8 的启用条件逐条对照）：

1. 规则基线在评测集上 100%，**没有可被小模型补的召回缺口**；
2. 两个小模型都存在 6–9 条**危险方向误判**（S1 解释题 → S2 模板），而线上评审门槛应为「危险方向 = 0」；
3. 延迟（P50 0.5–0.7s）虽可接受，但为 0 收益引入额外依赖/成本/失败面，不符合「不为改造而改造」；
4. 若未来线上低置信样本显示规则确有漏判，可重新评审，但须先满足：
   - 评测集 dangerous = 0（或加确定性仲裁层后 dangerous = 0）；
   - S2 recall ≥ 规则基线；
   - 仅对低置信样本调用、失败 open 到 S1、永不碰 S0（docs/14 T8 原方案）；
   - 过 docs/08 A.4 / docs/12 A9 裁决。

**保留用途（离线）**：每月重跑本脚本，用于（a）监控小模型能力变化；（b）从 disagreements 里挖规则词表/仲裁缺口候选（本轮 15 条误判已确认全部由规则仲裁正确兜住，无新缺口）。
