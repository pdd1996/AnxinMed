> 用途：用**零模型 key** 的可复现路径，跑一遍「录入 → 确认 → 药箱/计划 → 咨询 → 相互作用」的模拟用户旅程，并记录观察指标。
> 前置：M8 关账（`m8-done`）；本机 PostgreSQL 18 已起；`app/.env` 已配 `DATABASE_URL`。

## 1. 起服务（手动观察用）

```bash
cd app
AI_MODE=fixtures pnpm dev     # api :8787 + web :5173
```

- `AI_MODE=fixtures` 时模型 I/O 回放 `app/e2e/fixtures/*.json`；
- 回放需要请求头 `x-test-scenario`（E2E 由 Playwright 注入）。**普通浏览器手动上传图片时没有这个头，回放会显式报 `AIUnavailableError`**——所以「拍照入库」的手动观察用 §2-A 的 headed Playwright，不要用裸浏览器传图。
- 手动浏览器只用于**不需要模型**的路径（§2-B / §2-C）。

## 2. 三个模拟场景

### 场景 A：处方拍照 → 草稿 → 确认 → 药箱/计划（headed 观察）

```bash
cd app
pnpm --filter @anxin/e2e exec playwright test specs/golden-cases.spec.ts:71 --headed
```

观察点（与 `golden-cases.spec.ts` 断言一一对应）：

1. 上传合成处方笺 → 通过质量预检（合成图会提示反光/模糊，点「仍要上传」）→ 进入确认页；
2. 确认页：唯一匹配「玻璃酸钠滴眼液」、剂量 1 滴 / 每日 4 次 / 滴眼 / 疗程 7 天、结束日期已推算；
3. 未勾选「已核对每次用量/频次/疗程 + 使用人」前，确认按钮不可用；
4. 勾选后确认 → 跳药箱；药箱出现新药 + 生效计划；
5. DB：`drafts.status='confirmed'`、`drugs.confirm_status='transcribed'`、`plans.status='active'`、`sources.type='prescription'`。

预期：通过；失败时先看 Playwright trace（`app/e2e/test-results/*/trace.zip`）。

### 场景 B：手动建档药 → 只走 L0（手动浏览器）

1. 打开 <http://localhost:5173/box>；
2. 找到「盐酸二甲双胍片」（p-001 演示药，`confirm_status='manual'`），点「问这个药」→ 跳到 `/consult?drugId=…`；
3. 提问：「这个药通常用于什么？」。

预期：

- 返回 `manual-gate`：出现「手动建档 · 未经 OCR 确认，仅可做资料查询」类提示；
- **不出现**个体化解释/剂量建议；
- 该行为不依赖模型 key；后端日志有 consult 记录。

> 为什么保持 manual：M9 不伪造 `confirm_status`。这四个演示药就是 manual 数据，用来演示门禁；要演示 L1，请走场景 A/自动化的 `transcribed` 路径。

### 场景 C：生效计划 → 相互作用检查（手动浏览器，0 次 LLM）

1. 打开 <http://localhost:5173/consult>（不选药）；
2. 提问：「这些药一起吃有冲突吗」。

预期：

- 命中 `interaction-check` 数据直答（`toolUsed=interaction-check`，0 次 LLM）；
- 出现 2 条命中：`ir-001` 氨氯地平×阿托伐他汀、`ir-002` 二甲双胍×格列吡嗪；
- 每条带「需监测」级别 + note + 来源；同时提示规则库覆盖有限；
- 移动端会对 demo 条目显示「演示抄录 · 非正式规则库」徽章；web 患者端 H5 冻结，暂不显示徽章（M8 L6）。

### 场景 D（可选）：移动端

- `pnpm --filter @anxin/mobile android:dev` 起真机/模拟器；
- 走 Box → 问这个药 → 看命中卡 demo 徽章；
- 需要 Android SDK/JDK 17，参照 `app/packages/mobile/README.md`。

## 3. 观察指标（每次模拟记录）

| 指标 | 采集方式 | 期望 |
|---|---|---|
| 录入到草稿耗时 | 页面耗时 / `timing` 日志 | ≤15s（不含模型延迟；live 未测，fixtures 应更快） |
| 草稿一次确认通过率 | 是否修改字段后确认 | 记录，不做阈值 |
| 失败码是否可见 | 断网/模型不可用/冲突场景 | 必须有中文错误码 + 下一步，无静默吞错 |
| 咨询 L0/L1 分流 | `consult_logs.status` / `l0Notice` | manual → L0；transcribed+reviewed → 可 L1 |
| 相互作用命中 | `interaction-check` 结果 | 2 条 demo 命中 + 覆盖提示 |
| 数据副作用 | 模拟后 `plans/records/drugs` 计数 | 记录；必要时按 §4 重置 |
