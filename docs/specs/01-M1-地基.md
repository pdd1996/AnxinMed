## T2. pnpm 单仓脚手架

**做什么**

1. `app/` 根建 `pnpm-workspace.yaml`（`packages: ['packages/*']`）、根 `package.json`（scripts 聚合：`dev` / `build` / `typecheck` / `test`，用 `pnpm -r --parallel`）；
2. 把现有 `packages/api` 从 npm 迁到 pnpm workspace 成员（删 node_modules 与 package-lock.json 重装）；
3. 新建 `packages/shared`（`@anxin/shared`）：源码 `src/`，导出入口 `src/index.ts`；
4. 新建 `packages/web`（`@anxin/web`）：Vite + React 19 + TS 脚手架，依赖 `@anxin/shared`；
5. 根 `tsconfig.base.json`：strict、`moduleResolution: bundler`、ES2022；各包 extends。

**完成标准**：`pnpm install` 一次成功；`pnpm -r typecheck` 通过；`pnpm -r exec vitest run`（此时可 0 测试）不报错；web 包 `pnpm dev` 能起 Vite 默认页。

## T3. 用户域六表 schema + 迁移

**做什么** 在 `packages/api/src/db/schema.ts` 追加用户域六表（资产域三表已完成，勿动其字段语义）：

1. **`users`**：Better Auth 兼容形态（`id text pk / name / email unique / phone / createdAt / updatedAt`，预留 `betterAuth` 所需的宽松结构即可，MVP 不接插件）；seed：p-001 张某某（演示用户）+ mock-data `patients` 其余 8 人。
2. **`drugs`**（用户药箱，≠ drug_master）：
   - `id / userId`；身份快照：`genericName / brandName / specification / form / manufacturer`（从 drug_master 唯一匹配**拷贝**或用户手填）；
   - `drugMasterId text?`：可反查资产库条目（手动建档为 null）；
   - `confirmStatus varchar enum('ocr_matched','transcribed','manual')`；
   - `stock jsonb`：`{ value: number, unit: string }`（滴/片/粒/支/袋/喷/丸，DOSE_UNITS 进 shared）；
   - `openedAt date?`；`expiry date?`；
   - `sourceId text?`（→ sources.id）；`confirmedAt timestamp`。
3. **`plans`**：
   - `id / userId / drugId`；`dose jsonb {value,unit}`；`frequency integer`；`times jsonb string[]`（"HH:MM"）；`route text?`；`meal text?`；
   - `cycleType enum('closed','open','stock')`；`startDate date`；`endDate date?`；
   - `status enum('active','paused','ended')`；
   - `source enum('prescription','manual')`；`sourceId text? / itemId text?`（反查来源与条目，PRD §7.3.1）；
   - `tags jsonb`：`Partial<Record<'dose'|'frequency'|'duration'|'times'|'startDate'|'endDate', TagKind>>`（四类标注，TagKind 定义进 shared）。
4. **`records`**：`id / userId / planId / scheduledDate date / scheduledTime text / status enum('taken','skipped','later') / actedAt timestamp`。（pending = 无记录，运行期推导，不落库。）
5. **`sources`**：`id / userId / type enum('prescription','drug_box','manual')`；`bodyImageRef text?`（正文裁剪图存储引用）；`whitelistFields jsonb`（L1 白名单字段快照）；`prescriptionNo text?`；`confirmTrace jsonb`：`{ confirmedAt, method, keyFieldsSnapshot }`（确认留痕，PRD §7.2.5）；`sanitizeAudit jsonb`：`{ [patternType]: count }`（L2 审计，只记类型与次数）。
6. **`health_profiles`**：`id / userId / fieldKey / value / sourceMeta jsonb`：`{ source: 'self_reported'|'prescription_confirmed', confirmedAt? }`（字段级来源标注，PRD §7.1.2）。

生成迁移进 `drizzle/`（纯 SQL 进 git）。

**完成标准**：`drizzle-kit generate` 无错误；对本地库 `db:migrate` 后 `\dt` 共 9 张表；`pnpm -r typecheck` 过。

## T4. shared 包：领域类型与 zod schema

**做什么**（以 `demo/src/types.ts` + `lib.ts` 为底本，按总纲 §2.5 对齐目标枚举）：

1. 枚举与常量：`ConfirmStatus / TagKind / CycleType / TaskStatus / SourceType / PlanStatus / RiskLevel('L1'|'L2'|'L3'|'L4')`、`DOSE_UNITS`、`TAG_META / CONFIRM_STATUS_META / CYCLE_META`（含中文 label/hint，照搬 demo）；
2. 纯函数：`todayStr / addDaysStr / daysBetween / estimateStockDays / suggestTimes / isPlanActiveOn`（照搬 `demo/src/lib.ts`，补单测）；
3. zod schema（`.strict()` 只用于 L1 白名单，M2 用；此处先建骨架）：`DrugDTO / PlanDTO / RecordDTO / HealthEntryDTO / SourceDTO`，与 DB 行结构对应（日期字段用 `string` 传输，ISO `date`/`HH:MM`）；
4. 白名单闭合 schema（M2 依赖，此处定契约）：`PrescriptionWhitelist`：`{ hospital, prescriptionNo, date, department, diagnosis, items: [{ drugName, specification, quantity, usage }] }`，`.strict()`；
5. 错误码常量：`ERR_CODES`（`UNSUPPORTED_OBJECT / LAYER_MISMATCH / OCR_FAILED / PARSE_FAILED / BACKLINK_FAILED / NOT_FOUND / VALIDATION / AI_UNAVAILABLE / RISK_INTERCEPTED / CONFLICT`）。

**完成标准**：`shared` 包被 api 与 web 同时 import 无循环依赖；Vitest 覆盖 lib 纯函数（每个函数 ≥ 3 case）；typecheck 过。

## T7. 药箱 / 计划 / 记录 API（demo 功能迁移，核心数据链路）

**做什么** 把 demo localStorage 数据链路迁到 DB，路由薄、逻辑进 `src/services/`、数据进 `src/repositories/`（Drizzle builder）：

- `GET /api/drugs`（列表，含库存推算天数 `estimatedStockDays`）、`POST /api/drugs`（手动建档，`confirmStatus='manual'`，写 sources type=manual 留痕）、`GET/PATCH/DELETE /api/drugs/:id`；
- `GET /api/plans`、`POST /api/plans`（手动建计划：字段全部来自请求体 + 默认值标注规则——开始日期缺省=今天 标 `default`；时间点缺省走 `suggestTimes` 标 `assist`；**此处不接规则引擎，M2-T5 接**）、`PATCH /api/plans/:id`（暂停/恢复/编辑/结束）、`DELETE`；
- `GET /api/tasks/today`：按生效计划（`isPlanActiveOn`）+ times 生成当日任务，与 records 对账得出每条任务状态（无记录=pending）；
- `POST /api/records`：body `{ planId, date, time, status }`（替代技术方案里的 `take|later|skip` 三条路由，等价且少重复；zValidator 校验）；同 planId+date+time 重复操作返回 409 `CONFLICT`（防重复二次确认的接口面）；
- 全部带 `resolveUser` 的 userId 过滤（多用户边界从第一天贯通）。

**完成标准**：集成测试（`app.request()`）覆盖：手动建档→建计划→today 生成任务→打勾→重复打勾 409；PATCH 暂停后 today 不再生成任务；typecheck 过。

## T11. OCR 实测定案（ADR #13）

> 注（2026-09-07）：OCR 选型已由 **ADR #16**（qwen3.5-ocr 云端 VLM 转录，见 docs/07 §五）取代；本节为 PaddleOCR 时期任务记录，实测存档见 `tools/ocr-bench/`，历史正文不改写。

**做什么**

1. 准备合成处方笺样张（PRD 附注：萧山区二院样例合成脱敏版；如暂无图片，生成一张打印体合成处方笺替代，并在结论中注明）；
2. 对两候选各跑最小实测：**PaddleOCR 自托管**（PP-OCRv4，`paddleocr` python 包或 docker 镜像）vs **阿里云高精 OCR**（通用文字识别，临时 key 放 .env）；
