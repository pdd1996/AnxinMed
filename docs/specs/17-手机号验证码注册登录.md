# P1 · 手机号验证码注册登录（阿里云短信认证）

> 日期：2026-11-18
> 性质：落地 [ADR #22](../07-技术选型决策记录.md)（ADR #11「手机号验证码」目标的 P1 先行形态）；与 G7 账号密码登录并行，不替换。
> 上游：[specs/12 §3 G7](../specs/12-M12-上线差距盘点.md) 剩余「自助注册/找回」；[PRD §7.1.1](../../docs/06-安心用药-产品需求文档-PRD-V2.md) 账户体系 P1。
> 范围：`app/`（shared / api / core / web / mobile）+ 本文档 + `deploy/` 运维配置；新增一条外部依赖（阿里云号码认证 · 短信认证）。

---

## 1. 目标与非目标

**目标（完成判据）**

1. 手机号 + 短信验证码即可完成**注册与登录**（验证码即注册：首次验码通过自动建号）；
2. 不破坏 G7 既有行为：账号密码登录、`AUTH_MODE=demo` 旁路、既有 API/Web/App/fixtures E2E 测试全部保持通过；
3. 失败可见：缺配置 `503 SMS_NOT_CONFIGURED`、发码频控 `429 SMS_LIMITED`、验证码错误 `401 AUTH_CODE_INVALID`，文案均为用户可理解中文；
4. 成本与滥用可控：同号 60 秒冷却 + 同 IP 每小时 10 次本地限流（在阿里云频控之外的前置闸门），验证码明文绝不返回/落日志。

**非目标（本次明确不做）**

- 自助改密 / 忘记密码（找回复用赠送模板 100003，接口下一步）；
  注：**登录后的「设置 / 修改密码」已于 2026-11-18 增补落地**（见 §2 D11 / §4 / §5），
  这里未做的是**未登录状态下的「忘记密码」自助找回**；
- 手机号换绑、账号注销（属 G14 数据生命周期）；
- 角色/权限模型与租户隔离（G7 已登记遗留，不因手机号登录改变）；
- 通知类短信 / 自定义签名（需企业认证 + 通用短信服务，见 ADR #22 重议触发条件）；
- 接入 Better Auth `phoneNumber` 插件：阿里云已托管验证码生成/核验，若再接自管 OTP 会出现两套验证码状态，故本期不接（ADR #22 保留该选项）。

## 2. 关键决策（与理由）

| # | 决策 | 理由 |
|---|---|---|
| D1 | 通道用阿里云「号码认证服务 · **短信认证**」，不用通用短信服务 | 个人实名即可用、免企业资质、免签名/模板实名报备、赠送签名+5 个标准模板、验证码生成与核验托管（**核验免费**）；App 未上架时通用短信服务的自定义签名报备走不通。日用价格：按量 0.06 元/次（月量 ≤1000 档），核验不计费、回执失败不计费 |
| D2 | **验证码即注册**：无账号自动建号（`u-<uuid>`），有账号直接登录 | 老年用户记不住账号密码；注册与登录合成一步，减少一次断点。G7 密码登录保留给老账号/管理员场景 |
| D3 | 验证码参数：**6 位数字 / 300 秒有效 / 60 秒重发** | 6 位兼顾安全与老年输入成本；有效期与模板变量 `min=5` 对齐；`Interval=60` 由阿里云频控兜底，前端倒计时同源 |
| D4 | 校验由阿里云 `CheckSmsVerifyCode` 完成，**我方不存验证码明文/哈希** | 平台托管生命周期（过期/覆盖/重试策略）；注意官方口径：`Code=OK` 只代表接口成功，**是否通过只看 `Model.VerifyResult === 'PASS'`**；`isv.ValidateFail`（错误/过期/被覆盖）归一为「未通过」，不报 500 |
| D5 | `users.phone` 唯一索引（PG 默认 NULLS DISTINCT）+ `phone_verified_at`；复用既有 `sessions` | 不新增会话体系；多行历史 `phone=null` 不冲突；最接近 ADR #11 的目标形态，后续换 Better Auth 只替换凭据层 |
| D6 | 本地限流：同号 60 秒 + 同 IP 10 次/小时（单实例内存） | 防「短信轰炸」把账户余额打光；与 G7 登录限流、G10 限流同构（`NODE_ENV=test` 默认关闭、`RL_FORCE=1` 强制开启；多副本前需换共享存储） |
| D7 | 仅 `AUTH_MODE=password` 可用；demo 模式明确 400 拒绝 | demo 已自动登录，不应出现验证码；与 G7 `/login` 的 demo 语义一致（明确拒绝，不静默发 token） |
| D8 | 并发首登由 `users_phone_uq` 唯一索引兜底，`23505` 回读已有账号 | 两个请求同时首登不产生双账号；查不到行则照常抛错（不静默吞） |
| D9 | web 登录页 / App `AuthGate` 双 tab（密码 / 手机号），不新增路由 | App 无 `RequireAuth + /login` 结构（G7 用登录门），新增注册路由会破坏四态门；复用同一 Card 内切换成本最低 |
| D10 | 发码响应回传 `signName`，前端展示「短信落款为 XX，请注意查收」 | 赠送签名不是「安心用药」，老年用户容易把验证码短信误判为诈骗；把落款提前告知是最低成本的防误判 |
| D11 | 登录后「设置 / 修改密码」（2026-11-18 增补）：无密码账号（手机号注册）直接设，**账号名自动取手机号**；已有密码账号改密必须验证当前密码；当前密码错返回 **400 `AUTH_PASSWORD_INVALID`** 而不是 401 | 手机号账号没有账号名/密码，密码登录入口无法使用；补密时账号名取手机号，老人不需要再编一个账号名。旧密码错不能用 401——前端把 401 统一当「登录失效」清登录态，改密页会被误踢下线。登录态已证明手机号归属，故无密码账号补密不要求二次短信（代价：会话被劫持时可改密，已在 §8 登记）。入口放「设置 → 账号与安全」而不是个人资料：密码是安全设置，个人资料只放身份展示信息；后续手机号换绑/账号注销（G14）也归此处 |

## 3. 数据模型（迁移 `drizzle/0013_powerful_talon.sql`）

| 变更 | 类型 | 说明 |
|---|---|---|
| `users.phone_verified_at` | timestamp（可空） | 手机号最近一次验证通过时间；老账号首次改用手机号登录时补记 |
| `users_phone_uq` | unique index on `users.phone` | 手机号登录标识唯一；`NULLS DISTINCT`（PG 默认）兼容既有未绑定用户 |

## 4. API 契约（`shared/src/auth.ts` 一份真相）

| 方法/路径 | 鉴权 | 说明 |
|---|---|---|
| `POST /api/auth/phone/send-code` | 匿名 | `{ phone }` → `{ mode, cooldownSec:60, expiresInSec:300, signName }`；失败 400 `VALIDATION`（手机号格式）、429 `SMS_LIMITED`、503 `SMS_NOT_CONFIGURED`/`SMS_SEND_FAILED` |
| `POST /api/auth/phone/login` | 匿名 | `{ phone, code }` → `{ mode, token, user:{id,name,username,hasPassword}, created }`；验证码不对 401 `AUTH_CODE_INVALID`（统一文案，不区分没发过/过期/输错）、503 `SMS_*` |
| `POST /api/auth/password` | Bearer | **设置/修改密码（P1 增补）**：`{ password, oldPassword? }` → `{ mode, user }`。无密码账号（手机号注册）只需 `password`（账号名自动取手机号，之后可用「手机号 + 密码」登录）；已有密码账号必须 `oldPassword`；当前密码错 400 `AUTH_PASSWORD_INVALID`、长度不足 400 `VALIDATION`、账号名冲突 409 `CONFLICT`、demo 模式 400 |
| 其余 `/api/*` | Bearer | 与 G7 完全一致（不变） |

新增错误码：`AUTH_CODE_INVALID` / `SMS_NOT_CONFIGURED` / `SMS_SEND_FAILED` / `SMS_LIMITED` / `AUTH_PASSWORD_INVALID`（设密/改密旧密码错，400，避免与登录 401 混用）。
对外用户对象仍只含 `id/name/username`（**不返回 phone/passwordHash**，既有零泄漏断言继续成立）。

## 5. 前端

**@anxin/core**（web/App 共用逻辑）

- `requestPhoneCode(phone)`：调发码接口，返回冷却/有效期/落款签名；失败原样抛给页面；
- `signInWithPhone(phone, code)`：成功后写 token 持久化并切 `authenticated`，返回 `{ created }`；
- 沿用 `AuthTokenStorage` / `setUnauthorizedHandler` 接缝，无平台分支。

**web**：`routes/Login.tsx` 双 tab。手机号 tab：11 位输入过滤、`获取验证码`（60 秒倒计时、冷却禁用）、落款提示、`登录 / 注册` 提交、错误内联 `role=alert`。
「设置 → 账号与安全 → 登录密码」（`routes/patient/Settings.tsx` 入口 + 二级页 `routes/patient/PasswordSettings.tsx`）：有密码显示「当前密码 + 新密码 + 确认新密码 / 修改密码」，无密码（手机号注册）只显示新密码两项 / 「设置密码」，成功后提示可用「手机号 + 密码」登录。密码是安全设置，不放进「个人资料」（那页只放姓名/头像这类身份资料）。

**App**：`components/AuthGate.tsx` 登录门内双 tab（不新增路由）。适老化：触控 ≥48/52px、错误内联保留在表单（读屏可播报）、键盘避让沿用既有 `KeyboardAvoidingView`。
`app/password.tsx`（设置 → 账号与安全 → 登录密码，根 stack 全屏页）与 web 同形：`secureTextEntry`、同一份 shared 契约校验、失败内联。

## 8. 已知风险与遗留（交付说明需抄录）

1. **单实例内存限流**：同号冷却/同 IP 小时配额随进程重启清零；多副本部署前需换共享存储（Redis/DB 计数）。
2. **仅中国大陆手机号**（服务端固定 `CountryCode=86`）；港澳台/国际号码不支持。
3. **落款为赠送签名**（如「恒创联众」），不是「安心用药」；前端已提示「短信落款为 XX，属正常」。正式上线需企业认证 + 自定义签名（走通用短信服务），会改变 provider 配置。
4. **未登录找回密码未做**：模板 100003 已具备，接口下一步；忘记密码仍走管理员 CLI 重置。登录后的设置/修改密码已落地
   （`POST /api/auth/password`）：手机号账号补密**不需要二次短信**（登录态即证明手机号归属），代价是会话被劫持时可被改密——
   接真实用户前建议加二次验证（短信/旧密码）并「改密即清其他 session」；当前改密**不撤销既有 session**（与 G7 同口径）。
   另：手机号账号设密后账号名=手机号，之后「密码登录」的账号就是手机号。
5. **合规前置未完成**：G4 告知同意/隐私政策、G14 数据生命周期（注销/删除/留存）未落地前，手机号注册仅限受控模拟试点，不接真实患者。
6. **外部依赖政策风险**：阿里云「短信认证」为 2025-11 推出的个人可用通道，后续资质/计费/签名政策可能调整；以官方最新说明与购买页为准（参考 [specs/13 已知风险](../specs/13-G7-最小账号密码登录.md) 的同类登记方式）。
7. **成本**：按量 0.06 元/次（≤1000 次/月档），受控试点量级约几元；核验免费、回执失败不计费；套餐包 1000 次 54 元/12 个月但**不支持自主退费**，小量阶段按量更划算。
