# M12 · 上线差距盘点（2026-11-17）

> 性质：**只盘点、不新增功能、不改数据**。目标是把「能演示」和「能上线」分开记账，给出一份可执行的 Go/No-Go 清单。
> 输入：M1–M11 产物、PRD §14/§16、M8 上线闸门（[08 文档](./08-M8-上线前收口.md) §5.5–§5.7）、本地实测。
> 结论不替用户/法律/临床做决定；只给证据、差距和关闭判据。

---

## §1 结论（先看这段）

| 目标 | 结论 | 说明 |
|---|---|---|
| **内部演示 / 模拟用户** | ✅ 可继续 | 功能回归全绿、demo 路径可跑；必须保留「演示抄录、非临床决策依据」标识 |

## §4 分档判断

### A. 内部演示（现在可以做）

前提：
- 只使用演示账号/模拟数据；页面上保留「演示抄录、覆盖有限、不构成医疗建议」；
- 不接真实患者、不用于临床决策；
- 演示脚本按 M9 手册走（拍照入库 L1 / 手动建档 L0 / 相互作用 0 LLM）。

### B. 受控模拟试点（建议 2–4 周后再评估）

最低门槛：
- G2 临床签核完成（至少 35 条级别定稿）；
- G4 有可给用户看的告知/同意/隐私说明；
- G5 staging 能部署、能备份、能回滚；
- G6 live 全链 P95 有数、降级可用；
- G7 有邀请制/登录（至少不能任意人访问）。

### C. 公开发布 / 临床使用（当前不可）

必须关闭 **G1–G5 全部 P0**，且由法律/医疗专业给出书面结论。工程侧不能替这两类签字。

## §5 建议的下一步（按顺序）

1. **T2 收口**：药师回传 35 条 → dry-run → 改 seed → apply（G2）；
2. **Live 长稳与成本**：`perf:consult-live` 已把全链 P95 跑到 5.2s；下一步 N≥50/持续采样、记录 token 成本与限流（G6 剩余部分）；
3. **staging 部署 smoke**：目标环境 compose 起服务、健康检查、备份/恢复演练（G5）；
4. **合规包**：数据授权、隐私/同意、第三方模型处理、免责声明（G4，需人）；
5. **reviewed 人工核验方案**：抽检比例、责任人、记录方式（G3）；
6. 以上有结论后，再决定是否做 batch3 规则/更多 UI。

**明确不做**：继续堆规则条数、用代理批量刷 reviewed、把 fixture E2E 当 live 证据。

## §7 证据边界

- 本盘的 live 数字来自本机单次探针（N=10，单一 prompt），**不是生产 SLO**；
