## 1. 一句话与改革依据

**把患者端咨询从「单轮无状态问答服务」升级为「有会话、有档案、有评估的技能路由式 Agent」——不加自主性，只补记忆、路由契约与可评估性。**

改革依据：对照 2025–2026 主流垂类医疗 Agent（蚂蚁阿福等）的通行架构——前置门 → 上下文组装 → 技能路由 → 受限管线 → 输出护栏 → 记忆回写 → 评估闭环——逐项核对本项目现状后的结论是：

- **骨架已经是正确形态，且部分领先**：守门前置（L4 > L3 先于一切）、事实与生成分离（数据意图 0 次 LLM、按键取数禁 RAG、规则库只抄录）、输出护栏（safeParse + 剂量过滤）、降级语义化（三模型 kill 演练）——这四项与生产级垂类 agent 的设计完全同构，是改革的地基，**不动**。
- **差距集中在四点**：单轮无状态、上下文注入近乎空集、技能路由未契约化、咨询质量无度量（详见 §2.2 D1–D4）。外加一个建设性缺失：咨询发现（新药、不适主诉）没有回到药箱/档案的确认式通道（D5）。
- **方向上刻意不做的事**：同类产品的「行动力」（自由规划、多步自主循环）在用药安全场景是负资产。本项目处在「自主性 × 出错成本」谱系的最高出错成本档，Agent 形态 = 对话主脑 + 受限技能管线，这个定位**不变**。

## 3. 设计原则（六条）

- **P1 低自主高管线**：Agent = 对话主脑 + 受限技能管线。不引入 ReAct/自由多步循环、不做 LLM 意图分类主路径（正则 + skillId 快路径够用；Qwen FC 仍是预留扩展位，启用依据 = R7 的漏判率抽检数据，与 ADR #17 补记口径一致）。
- **P2 事实与生成分离（守）**：数字与断言只来自查询/抄录，LLM 只解释——任何新技能上线前必须先定义「事实来源清单」。**安全关键的用户事实（过敏）同样不做模型上下文联想**：走「过敏关键词 ∩ 禁忌段」的确定性注入覆盖层，与相互作用注入同构（R4a）。
- **P3 档案即记忆（建）**：长期记忆 = health_profiles + 药箱，短期记忆 = 会话窗口。回写必须确认式；**建议卡由确定性规则生成，不是 LLM 生成**（与「医嘱只抄录不生成」同源的纪律）。
- **P4 技能显式化**：每个技能 = 注册表一行配置（触发、上下文需求、管线、输出 schema、守门、溯源、降级）。chips 走 skillId 快路径，自由文本走正则慢路径，「宁漏勿误」不变。
- **P5 可评估，且先织网**：每技能 golden 集 + 指标口径随技能一起交付，没有评估的技能不上线；**评估安全网（fixture 机制 + 不变量 golden）先于任何行为变更落地**——用产生方案时的判断去改行为之前，先把「改坏了能被发现」的网织好。
- **P6 降级语义化（守）**：新增依赖（会话窗口、档案注入、建议卡）任何失败不得阻塞主回答路径，禁止静默吞错。

## 4. 目标架构：一次提问的生命周期（v2）

```
会话解析（sessionId 可选；无则首答后建会话）
  → 前置门（不变：脱敏 → L4 急症 > L3 拒答，纯函数）
  → 上下文组装（v2，M3-T1 三要素做全）：
      对象药身份 + 说明书按键段落 + 相互作用规则（既有）
      + conditions 等交集陈述型档案字段（标注「用户提供、未经医学验证」）
      + 在服计划药名全集 + 会话窗口（最近 N 轮已脱敏文本，纯函数截取）
  → 技能路由（v2）：skillId 快路径（chips/深链直达）→ 正则意图 → 说明书管线兜底
  → 技能管线执行（S0–S3，见 §5；全部受限管线，无自主循环）
  → 过敏覆盖层（v2，确定性纯函数，位于管线输出后）：
      档案过敏关键词 ∩ 对象药禁忌段命中 → sections.risks 追加固定警示
      + citations 追加禁忌段引用；不经模型联想，不改 riskLevel、不进 risk_events（提示非拦截）
  → 输出守门（不变 + 强化）：safeParse → 归一化 → 剂量过滤 → 引用注入完整性校验
  → 留痕（扩展）：consult_logs 带 sessionId/turnNo/intent
  → 建议卡生成（v2 后处理）：确定性规则 → pending 卡片
      （透明告知 L0 门禁差异：手动建档仅可查说明书资料；拍照/手动双路径），
      用户确认才走既有建档入口
```

## 6. 数据与契约变更

### 6.1 API 契约修订（需 §9-1 裁决）

- `POST /api/consult` 请求体增**可选**字段：`sessionId?`（续问）、`skillId?`（chips 快路径）；响应体增 `sessionId`（首答回传）。无这两个字段 = 与今天行为完全一致（向后兼容）。
- 新增只读端点：`GET /api/consult/sessions`（列表）、`GET /api/consult/sessions/:id`（按 turnNo 回放 consult_logs）。
- 新增建议卡端点：`POST /api/consult/suggestions/:id/accept`（body 带 `path: 'ocr' | 'manual'` 建档路径）、`POST /api/consult/suggestions/:id/dismiss`。

### 6.2 表变更（迁移为纯 SQL 进 git）

- 新表 `consult_sessions`：`id / user_id / title(首问截断) / created_at / last_active_at`。
- `consult_logs` 加列：`session_id / turn_no / intent`（intent 可空 = 说明书管线兜底，对齐 `insight_ask_logs.intent` 漏判留痕口径）。
- 新表 `consult_suggestions`：`id / session_id / consult_log_id / type(add_drug|note_symptom) / payload(jsonb) / status(pending|accepted|dismissed) / acted_at`。

### 6.3 shared 契约收编

- 快捷问题提升为 shared 契约：`QuickQuestion[] = { label, question, skillId, intent? }`——web chips 渲染与后端路由**同源**，废除「改文案必须人工核对正则」的脆弱耦合。
- 意图正则表（`INTENT_ROUTES` / `EXPLAIN_INTENT_PATTERN`）保持 api 导出、shared 引用其类型（正则本体仍在 api，避免 web 误用为前端预判）。

## 7. 分阶段任务（R1–R8，批准后升格为任务书）

> **执行顺序原则：先织安全网，再做行为变更。** 评估安全网（R7 的机制与不变量部分）先于一切行为任务落地；行为任务各自重录逐字节 fixture。推荐顺序：
> **R1 → R7（机制与不变量）→ R2a → R4a → R3 → R6 → R2b → R4b → R5 → R8**
> 优先级：P0 = R1 / R7 / R2a / R4a / R3 / R6；P1 = R2b / R4b / R5 / R8。**若只做一半，做完 P0 即停**——P0 交付的是过敏覆盖层、会话、建议卡闭环与评估网，P1 是深化与卫生。

### 阶段〇 · 安全网与契约（P0，先织网）

**R1 文档债清偿与契约收编（P0）**
- 修复 PRD「沿用 V1」断链：咨询细则（可答/拒答范围、回答结构、上下文确认）重锚为成文规定（落点见 §9-2）；`.qoder/` 意图路由设计说明收编进 docs（落点见 §9-6）。
- 快捷问题契约落 shared（§6.3）。
- 完成标准：断链修复方案经用户确认落盘；shared 契约 + web/api 同源改造；`pnpm -r typecheck` + web/api 测试全绿。

**R7 评估安全网与指标口径（P0，本任务前置执行；基线收口在 R8 前）**
- 前置部分（阶段〇）：① FixtureAiClients 扩展 consult LLM 场景回放机制（对齐录入线 fixture 机制）；② **不变量 golden**——断言不随 prompt 演进漂移的契约面：响应结构、守门行为（L4/L3/limited）、非拦截回答 citations 三件套非空、降级语义（AI_UNAVAILABLE → 规则拼装）；③ 指标口径定义落文档。
- 后置部分（R8 前）：逐字节 fixture 随各行为任务重录（R3/R4/R5/R6 改 prompt 后旧录制失效）；指标基线数字收口。
- 指标口径：L4/L3 拦截召回 = 口语变体 golden 全过（静态保证）；意图漏判率 = **人工标注抽样集为分母**（初期每月抽 30 条 consult_logs 人工标注应路由意图，非实时指标）；strip 触发率 = limited 占比；全链 P95（目标值见 §9-5）；建议卡接受率。
- 完成标准：不变量 golden 全绿且覆盖上述四类契约面；fixture 机制演示一条 consult LLM 路径回放；指标口径文档化。

**R2a 技能注册表纯重构（P0，零行为变更）**
- `SkillRegistry` 纯函数配置表统一 S0–S3 分支（现状 guard/intent/runConsult/runDataQuery 的显式化），不引入任何新行为。
- 完成标准：**既有测试断言语义不变全绿**——允许改 import 路径与测试文件结构，不允许改任何断言；新增注册表自身单测（分支覆盖 = 既有分支一一对应）。

### 阶段一 · 高价值行为变更（P0）

**R4a 过敏确定性覆盖层（P0，独立于会话/注入，零 LLM）**
- 纯函数 `allergyOverlay(allergyFields, insert.contraindications)`：命中 → `sections.risks` 追加固定警示条目 + citations 追加禁忌段引用；不命中 → 原样返回。位置在 S1 管线输出后、守门归一化后附加；**不经模型、不改 riskLevel、不进 risk_events**（提示非拦截，与相互作用注入同构）。
- 完成标准：纯函数单测（命中/不命中/多过敏词/无档案/禁忌段缺失）；集成测试：档案含过敏词 + 对象药禁忌段含该词 → 回答附加警示且**既有回答内容不变**；E2E 断言覆盖层不新增任何 LLM 调用。

**R3 会话层（P0）**
- §6.2 表变更 + §6.1 契约修订；前端会话持久化、历史列表入口、恢复窗口；无 sessionId 行为 = 今天。
- 完成标准：迁移 SQL 进 git；集成测试覆盖 userId 隔离（跨用户不串会话）、首答回传 sessionId；web 会话列表/恢复测试；E2E 一条「会话内续问」golden（含 fixture 重录）。

**R6 确认式建议卡（P0）**
- 确定性规则（非 LLM 生成）：`add_drug`（提问命中 drug_master 通用名/商品名规范化匹配、且未在用户药箱 → 「加入药箱」卡）；`note_symptom`（纯引导卡，不落库，见 §9-4）。频控：每轮 ≤1 卡、每会话 ≤3 卡，dismissed 不再触发。
- **卡片透明告知 + 双路径**：文案明示「手动建档仅可查说明书资料（L0）；拍照建档保留完整咨询」，接受时带 `path: 'ocr' | 'manual'`——拍照走既有 M2 OCR 录入线（confirmStatus=ocr_matched，保有全部咨询权），手动走既有手动建档预填；两条路径都经既有确认页，**不新增任何写路径**。
- 完成标准：规则纯函数单测含**不误报案例**（问已入库药不弹卡）；「无用户确认零写入」集成红线断言；卡片文案含 L0 门禁差异告知的 UI 断言；两条路径 E2E 各一条 golden；建议卡留痕落 `consult_suggestions`。

### 阶段二 · 深化（P1）

**R2b skillId 快路径 + 今日待服意图（P1，新行为）**

- 完成标准：skillId 快路径集成测试（正则不命中的自由写法 + skillId 命中同路径）；next-dose golden；`consult_logs.intent` 落列并有集成断言。

**R4b conditions 交集注入（P1）**
- prompt 注入「用户自述慢病（用户提供、未经医学验证）」块，回答模式硬性约束为**「说明书事实 × 用户事实的交集陈述，禁止推断」**；`buildConsultRequest` 扩展。
- 完成标准：ai-clients 请求体白名单断言更新（新注入块逐字段断言，PII 零泄漏断言扩展）；「注入前后守门/过滤行为一致」专项 golden（注入 conditions 后，拒答/剂量过滤行为与不注入时逐例一致）；骨架（不含 LLM）P95 基准附报告。gender/birthMonth 等个体化倾向最强字段**不在本期**（说明书老年用药段本有相关内容，注入增益小、推断风险大）。

**R5 多药与溯源强化（P1）**
- 多药对象全量注入：主药按键段落 + **其余对象药身份快照**（替代 `pickPrimaryDrug` 单药截断；相互作用上下文既有逻辑不变）。
- citations 升级段落级锚点（`sectionKey`），前端折叠展示透传。
- 引用注入完整性纯函数：citations 引用的段落/规则 ∈ 本轮实际注入集合（注入集合作为管线产物传给校验）。
- **明确声明**：citation-washing（回答内容不忠实于所引段落）为**接受的残余风险**——不做 NLP 断言检测（要么恒真要么误杀），缓解 = 既有「只基于给定段落回答」prompt 硬性规则 + R7 golden 抽样复审。
- 完成标准：两药场景集成测试（prompt 断言双药身份）；锚点透传 web 测试；注入完整性纯函数单测。

### 收尾 · 验收与增补

**R8 验收与 PRD 增补（P1）**
- PRD §15 增咨询指标、§16.3 增验收条目（会话续问 / 段落锚点 / 建议卡确认门与双路径 / 今日待服 / 过敏覆盖层）；逐字节 fixture 全量重录与基线数字收口；全量回归 + 360×740 仿真自验（会话列表、建议卡、多药回答、续问窗口）。
- 完成标准：增补条目逐项通过并附证据；`pnpm -r typecheck` + 全部测试 + E2E 绿。

## 8. 明确不做（非目标）

- 不做自主规划循环 / 多 Agent 协作 / Function Calling 主路径（Qwen FC 维持扩展位，启用依据 = 漏判率抽检数据）。
- 不上 RAG / 向量检索 / 全文搜索（PRD 决策 #15，且按键取数在当前规模是正确选择）。
- 不做 LLM 生成建议卡、LLM 生成档案条目、LLM 生成相互作用内容；**过敏不做模型上下文联想**（走确定性覆盖层）。
- 不做 NLP 断言检测类「引用一致性检查器」（citation-washing 按接受的残余风险处理，见 R5）。
- 不做主动推送 / 主动提醒（docs 留白项，留待下一期）。
- 不做跨用户任何数据共享；不做药盒/标签自动抄录（PRD §0.1 V2.1 已删除）。
- 不改医生端 ADR #17/#18/#19 架构与 MCP 工具面。

## 10. 风险与对策

| 风险 | 对策 |
|---|---|
| 会话窗口 + conditions 注入使 prompt 膨胀 → 延迟/成本上升 | 窗口定长（6 轮）+ 注入块字数上限；R4b 附骨架 P95 基准，超限即收紧 |
| conditions 注入诱发模型个体化倾向 | 回答模式硬性约束为「交集陈述、禁止推断」+ 守门不变 + R4b 注入前后行为一致专项 golden（golden 是缓解不是保证，故字段范围从严：仅 conditions） |
| **citation-washing**（回答不忠实于所引段落） | 接受为残余风险（不做 NLP 断言检测）；缓解 = prompt「只基于给定段落」硬性规则 + R7 golden 抽样复审 |
| 建议卡打扰老年用户；或加药后因 L0 门禁产生「刚加的药用不了」困惑 | 频控（每轮 ≤1、每会话 ≤3）+ dismissed 不复弹；卡片文案透明告知 L0 差异 + 拍照/手动双路径自选 |
| fixture 与 prompt 演进不同步（R3/R4/R5/R6 改 prompt 后旧录制失效） | 不变量 golden 断言契约面而非逐字节内容，不随 prompt 漂移；逐字节 fixture 按行为任务各自重录并纳入该任务完成标准 |
| consult fixture 录制依赖真实百川、输出不定 | 录制一次、脱敏后入 git，E2E 只做回放（与录入线 fixture 机制同款） |
| 会话历史引入新泄露面 | 窗口文本复用落库前已脱敏文本，注入前再 scrub 一道（双保险），零泄漏断言扩展覆盖 |
| 会话数据无限增长 | MVP 不删除（单用户量级可控）；保留策略列入下一期 |
