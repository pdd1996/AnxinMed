# 安心用药 AnxinMed · 大模型选型与改造方案

> 版本：V1.1（2026-09-23 落地修订：S3 清理 + P0 三任务实施，见 §10）  
> 日期：2026-09-22（V1.0）/ 2026-09-23（V1.1）  
> 范围：拍照录入、咨询、医生摘要、规则审方  
> 原则：大模型只负责理解和解释，不负责当药典。

---

## 0. 一句话

默认文本用 **通用、非思考** 的 `qwen3.8-flash`；视觉/OCR 继续通义；相互作用和剂量继续规则引擎；百川退出默认咨询主脑。DeepSeek V4.1 Flash 关思考后只做对照，打赢咨询 golden 再切流量。

不要上医疗垂类模型当发言人，也不要开思考档冲击「说明书转写」。

---

## 1. 产品事实（以代码为准，不以「医疗大模型」名片为准）

安心用药是老年慢病数字药箱：管依从、管冲突、管效期。AI 边界已写死：

- 不诊断、不开方、不调整用药方案
- 所有 AI 产出只是草稿，确认页才是入库闸门
- 咨询基于本地说明书库，四级守门 + 落库审计
- 相互作用 / 剂量 / 过敏由规则引擎标注，模型不得改判
- 医疗搜索兜底已移除（ADR #20：无源问题诚实拒答 + consult_logs 留痕作扩库采购单）

`AiClients` 实际调用只有这些：

| 方法 | 当前实现 | 任务本质 |
|---|---|---|
| `detectLayers` / `extractIdentity` | `qwen3-vl-plus` | 看图抽字段 |
| `runOcr` | `qwen3.5-ocr` | 医嘱行级抄录 |
| `fallbackParse` | CONSULT_PROVIDER 装配（默认 qwen3.8-flash 非思考） | OCR 文本补字段 |
| `consultAnswer` | 同上（deepseek-flash 对照；baichuan 回滚） | 给定说明书段落 + 规则文本 → 分区回答 |
| `insightSummary` / `queueSummary` | 同上 | 叙述已算好的统计 |

咨询进模型前，急症 / 拒答 / 无说明书已被守门挡掉。模型挂了走 `fallbackSectionsFromInsert`。  
因此咨询要的不是「更会看病」，是：少加戏、JSON 稳、秒级返回、和视觉同一套管线。

医疗模型（百川 M、华佗等）的训练目标是问诊和推方案，与产品 A1「用药管家不是预问诊医生」相反。ADR #17 已记录百川当时不吃 function calling，医生端只能先算数字再叙述。

## 2. 架构决议

| # | 决议 |
|---|---|
| R1 | 事实与生成分离。数字、用量、相互作用、过敏全部来自查询或抄录；LLM 只转写给定段落 |
| R2 | 自主性按出错成本分级。录入与计划近 0 自主；咨询只解释；医生端只叙述 |
| R3 | 视觉与文本可同厂商，但咨询请求不得带图。视觉能力闲置即可，不必找「关视觉」开关 |
| R4 | 咨询 / 摘要 / fallbackParse **强制非思考**。思考只允许出现在离线审核实验 |
| R5 | 医疗垂类模型若使用，只做审核器（抓「超出 citations」），不做发言人 |
| R6 | 双厂商可以，但默认路径尽量一家。第二家只做对照或灾备 |

逻辑分层保持现有六层：交互 → 技能 → 编排 → 事实（三库+规则）→ 数据。上层不能穿透下层写边界。

```
拍照录入
  qwen-vl / qwen-ocr     → 草稿
  用户确认页             → 唯一入库闸门

冲突 / 剂量 / 过敏 / 急症
  规则引擎 + 三库         → 零次 LLM

咨询回答 / 医生摘要 / 字段补全
  qwen3.8-flash
  enable_thinking=false
  preserve_thinking=false
  temperature=0
  response_format json_object
  失败 → fallbackSectionsFromInsert

对照（小流量）
  deepseek-flash + thinking.type=disabled
```

## 3. 模型选型

### 3.1 默认配置

| 链路 | 模型 ID | 思考 | 说明 |
|---|---|---|---|
| 图层 / 药盒身份 | `qwen3-vl-plus` | 关或保持现网 | 先不换厂商，有 OCR 黄金样张再评是否升 3.8 视觉 |
| 医嘱行转录 | `qwen3.5-ocr` | — | 相对本机 PaddleOCR 已验证；勿为「最新」重测除非行序/药名召回有数据 |
| 咨询 / 摘要 / fallbackParse | **`qwen3.8-flash`** | **必须关** | 速度与中文改写的平衡点；与 VL/OCR 同门 |
| 规则审方 | 无模型 | — | 十八反、剂量、过敏、急症继续硬规则 |
| 对照 | `deepseek-flash` | **必须关** | 同一套 prompt + golden，赢了再切 |

### 3.2 明确不用

| 模型 | 原因 |
|---|---|
| 百川作默认咨询脑 | 与产品边界错配；工具调用弱；双厂商无收益 |
| 百川 M4 / 华佗 / 神农 | 会把产品拽向类问诊 |
| `qwen3.8-max` / `qwen3.8-max-preview` | 能力过剩；部分预览关思考会 400 |
| `glm-5.3` / `glm-5.3-flash` | 官方不能 `thinking.type=disabled` |
| Kimi K3 | 旗舰 Agent，咨询用不上；部署/容量不适合 MVP |
| 任意默认思考档 | 延迟和「发明医嘱」一起上升 |

### 3.3 为什么咨询是 3.8-Flash 而不是 V4.1 / Plus / Max

速度 + 交付质量（字段合法、忠于引文、老人能懂、P95 短）一起看：

1. **`qwen3.8-flash` 关思考**：快、便宜、同门、可关思考。视觉闲置无妨。  
2. **`qwen-plus`**：默认就关思考，更省心，略慢。怕漏传参时当备胎。  
3. **`deepseek-flash` 关思考**：同一档用法，第二家供应商；必须用 golden 证明不更爱加戏。

V4.1 可以当默认，但必须写死关思考并断言无 `reasoning_content`。不关思考，就是用高 effort 推理模型做抄写，又慢又越权。

3.8-Flash / V4.1 Flash **默认都开思考**，和老 Plus「默认关」相反。选型后必须在客户端写死关闭，不能靠模型默认。

### 3.4 视觉关不掉，也不用关

多模态模型没有「关闭视觉理解」开关。不传 `image_url` / 视频就是纯文本。  
咨询接口产品层禁止收图；拍照只走录入管线。

## 4. 调用契约（必须写进客户端）

### 4.1 千问咨询（默认）

```
POST /compatible-mode/v1/chat/completions

{
  "model": "qwen3.8-flash",
  "temperature": 0,
  "response_format": { "type": "json_object" },
  "messages": [ /* 仅文本；禁止 image_url */ ],
  "extra_body": {
    "enable_thinking": false,
    "preserve_thinking": false
  }
}
```

历史消息不得回传 `reasoning_content`。3.8 系列 `preserve_thinking` 默认 true，不关会把旧思维链再次计费并污染上下文。

### 4.2 DeepSeek 对照

```
{
  "model": "deepseek-flash",
  "temperature": 0,
  "thinking": { "type": "disabled" },
  "messages": [ /* 仅文本 */ ]
}
```

不要再传 `reasoning_effort`（除非值为 `none`）。  
官方默认思考 + effort=high。漏关即失败。

### 4.3 成功判定

一次咨询调用只有同时满足才算成功，否则走说明书降级：

1. HTTP 成功且 JSON 能过现有 `ConsultRawSections` zod  
2. 响应无 `reasoning_content`，或 `reasoning_tokens === 0`  
3. 分区文本未出现剂量数字 / 停药 / 换药 / 诊断，除非原文段落已有  
4. 延迟超过咨询预算（建议单次模型 P95 ≤ 4s，全链 ≤ 15s）则记慢调用，连续超标告警

## 5. 工程改造清单

现有 `AiClients` 注入接缝保留，不推翻编排。

### 5.1 配置

在 `app/.env.example` 增加（名称可按仓库风格微调）：

```
CONSULT_PROVIDER=qwen          # qwen | deepseek | baichuan
CONSULT_MODEL=                 # 缺省 qwen3.8-flash；空串视同未设
# 思考开关不设 env：enable_thinking / thinking.type 在客户端代码写死（R4），漏关由响应断言兜底

DEEPSEEK_API_KEY=
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash

# 兼容保留，不再作为默认
BAICHUAN_API_KEY=
BAICHUAN_BASE_URL=
BAICHUAN_MODEL=
```

`QWEN_API_KEY` / `OCR_*` 保持录入链路不变。

### 5.2 代码

1. 新增 `app/packages/api/src/lib/ai/qwen-text.ts`（或扩展现有 `qwen.ts`）实现  
   `fallbackParse` / `consultAnswer` / `insightSummary` / `queueSummary`  
   强制 `enable_thinking: false`。
2. 新增 `deepseek.ts` 对照实现，强制 `thinking.type=disabled`。
3. `registry.ts` / `createAiClients()` 按 `CONSULT_PROVIDER` 装配文本方法；视觉方法仍走 Qwen VL/OCR。
4. 解析层：若出现 `reasoning_content`，记审计日志并视为失败（可配置为 strip 后仍用 `content`，默认失败更安全）。
5. 咨询 prompt 保持「只改写给定段落、禁止个体化推断」；`conditions` 继续只允许交集陈述。
6. E2E `AI_MODE=fixtures` 不变；新增/重录咨询 fixture 时用非思考输出。
7. 文档：ADR 新增一条「咨询文本模型从百川迁到 Qwen3.8-Flash 非思考」；改 README 环境变量表。

### 5.3 不要做

- 不要为咨询自训医疗模型  
- 不要把药典微调进权重替代三库  
- 不要 text-to-SQL  
- 不要让模型做相互作用和剂量  
- 不要 C 端直接给「可以吃 / 不能吃」的终裁（规则可标注，人确认）

## 6. 评测与上线门槛

用现有 M4 咨询口径，不要用 HealthBench / 编程 Arena。

### 6.1 必测集

- 规范性：用法、饭前饭后、漏服怎么说（只许复述说明书）  
- 负例：用户报糖尿病/肾功能，说明书未写调整 → 不得建议改剂量  
- 负例：问「能和 XX 一起吃吗」→ 只许复述规则引擎文本，不得脑补新相互作用  
- L3/L4 口语变体：仍应在进模型前被守门拦住  
- schema：缺字段、markdown 围栏、中英混杂  
- 降级：拔 key 后必须走说明书拼装且有 notice

### 6.2 通过线（建议）

相对当前百川基线：

| 指标 | 门槛 |
|---|---|
| schema 合法率 | ≥ 99% |
| 高危加戏（发明剂量/停药/诊断） | = 0（抽样集） |
| 引文不忠（citation-washing） | 不差于百川 |
| 模型 P95 | ≤ 4s（非思考） |
| 全链 P95 | ≤ 15s（现口径） |
| 思考泄漏率 | = 0 |

DeepSeek 对照同一套题。未全面优于或持平 Flash，不得切默认。

## 8. 风险

| 风险 | 缓解 |
|---|---|
| 3.8-Flash / V4.1 漏关思考 | 代码写死 + 响应断言 + 单测覆盖「带 reasoning 即失败」 |
| 多轮把思维链回传 | `preserve_thinking=false`，sanitize 历史 |
| 多模态误收图 | 咨询 API 校验 content 仅为 string |
| 说明书版权 / 过期 | 继续 reviewed 入库台账，不把爬虫草稿当生产真相 |
| 把 Flash 当成「更强医生」去开思考 | 产品评审拒绝；思考仅离线审核 |

## 9. 最终配置一览

```
录入视觉     qwen3-vl-plus
录入 OCR     qwen3.5-ocr
咨询默认     qwen3.8-flash + enable_thinking=false + preserve_thinking=false
咨询对照     deepseek-flash + thinking.disabled
咨询备胎     qwen-plus（默认非思考）
审方         规则引擎 + 三库，零 LLM
发言人       通用非思考模型
审核器       可选，后期再说，不进 MVP
```

安全来自闸门、zod、三库按键取数、用户确认页，不来自模型名片上的「医疗」或参数量。
