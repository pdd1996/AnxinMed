# A/B 质量基线 · H5 链路 vs RN 链路（M5-T4 完成标准第 2 条）

> 目的不是评「哪个 UI 好看」，而是回答一个问题：**把录入主线从浏览器搬到安卓壳里之后，采集端有没有把识别质量拖下去**。
> 口径来自 [05 任务书](../../../docs/specs/05-M5-安卓迁移与服务端上云.md) T4 与
> [05c 执行书](../../../docs/specs/05c-M5-T4-骨架冲刺执行书.md)：**同批 ≥10 张真实药盒照片，两条链路各跑一遍**。
> 10 张是**绊线口径**（只拦粗大差异）；任一指标显著劣于 H5 且归因到采集端 → 加样至 ≥30 张复测确认，再触发 §9 止损线 1。

## 两端各自的跑法

| 端 | 入口 | 本地质量预检 | 备注 |
|---|---|---|---|
| H5（冻结兜底，真相基线） | 浏览器 `http://118.196.82.13:8787/` → 拍药品 | **有**（canvas 像素统计：过暗/反光/模糊/分辨率低） | 预检是建议不拦用户，可「仍要上传」 |
| RN（M5-T4 骨架） | 真机「安心用药」→ 拍药盒入药箱 | **一期降级为不做**（05 任务书 T2/T4 明确允许；core 收 `stats: null` 即视为主流程照走） | 二期补 expo 侧像素统计后，本列才与 H5 同口径 |

因此**「预检触发」这一列两侧天然不等**：RN 恒记「未触发（一期降级）」，它不是质量差异，不能用来判止损。
真正可比的三项是：**首轮入箱成功率**、**重拍次数**、**降级/需人工补的条目占比**。

## 控制变量（做不到就别记这张表，改了再测）

1. **同一批照片文件**：两边都用「从相册选一张」，不用相机现拍（RN 侧 `quality: 0.8` 会重编码，与 H5 的原始文件不同源）；
2. 同一台手机、同一网络（都走公网火山 `118.196.82.13:8787`）；
3. 同一份服务端配置（`AI_MODE` 为空 = 真实模型，禁 fixtures 回放混跑）；
4. 每张照片两边各跑一次即清空药箱测试数据（或换用不同药品，避免「库内已有 → 唯一匹配」影响第二条的判定）。

## 判定与后续

- 首轮入箱率差 **≤1 张**（10 张口径下的噪声带）→ 记「无粗大差异」，T4 通过，继续 T5；
- RN 明显更差且**归因到采集端**（同一张原始照片在 H5 能过、在 RN 不过 → 指向 `quality: 0.8` 重编码、尺寸压缩或 dataURL 体积路径）→ 加样 30 张复测；仍复现则触发止损线 1（录入链路重估）；
- RN 更差但**归因到非采集端**（网络超时、地址没配好、服务端 5xx）→ 属环境问题，记进交付说明，不计入基线；
- 每次改 `quality` / 分辨率参数都要重跑本表，并在备注里写明参数值。
