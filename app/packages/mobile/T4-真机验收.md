## 0. 前置（一次配好，约 3 分钟）

### 0.0 【本机】这台机器第一次跑 mobile：先补 workspace 链接

```bash
cd app && pnpm install --frozen-lockfile && ls packages/mobile/node_modules/@anxin
```

预期：列出 `core/  shared/` 两个链接。缺了它们，构建会在 metro 打包期才炸，报错长这样：
`Unable to resolve module @anxin/shared from .../src/app/box.tsx`——**不是代码问题**，是依赖没链上。

### 0.1 【本机】起本地 API（dev 联调用，端口 8787）

```bash
cd app && pnpm --filter @anxin/api dev
```

预期：日志出现 `Listening on http://localhost:8787`（另开一个终端窗口验证，保持它运行）。

```bash
curl -s http://127.0.0.1:8787/api/health
```

预期：`{"ok":true,"data":{"status":"ok",...}}`

### 0.2 【本机】防火墙放行 8787 入站（**只加在专用网络会漏**：新连的 Wi-Fi 常被 Windows 判为公用网络）

PowerShell（管理员）执行，已存在同名规则会报「已存在」，可忽略：

```powershell
New-NetFirewallRule -DisplayName "anxin-api-8787" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8787 -Profile Any
```

### 0.3 【本机】确认电脑局域网地址（脚本会自动探测，这一步只是让你知道手机该连哪个网）

```bash
cd app/packages/mobile && pnpm env:print
```

预期：`[dev-url] EXPO_PUBLIC_API_URL = http://192.168.x.x:8787 （来源：探测：WLAN/无线局域网适配器）`
——多网卡/挂着 VPN 时会打印其他候选；手机连的是哪个网络，就用 `ANXIN_LAN_IP=那个IP pnpm env:print` 复核。
若来源显示 `.env.local`，说明本机钉死了地址：钉的是 `10.0.2.2` 就只有模拟器能连，真机必失败（该文件默认已全注释）。

### 0.4 【手机】连与电脑**同一个 Wi-Fi**，浏览器打开上一步的地址

`http://192.168.x.x:8787/api/health` → 预期看到 `{"ok":true,...}`。
打不开就是网络/防火墙问题，先解决它（后面的步骤都依赖这条）。

### 0.5 【本机】手机连上 adb

USB 插入并在手机上允许调试，或按 T3 的无线 adb 流程：

```bash
adb devices
```

预期：列出设备序列号 + `device`（不是 `unauthorized` / `offline`）。

## 1. 装机（二选一）

**A. 开发调试（改代码即生效，推荐先走这条）**

```bash
cd app && pnpm --filter @anxin/mobile android:dev
```

预期：metro 起来 → 自动 `expo run:android` → 手机上出现「安心用药」，首页三张卡：拍药盒入药箱 / 我的药箱 / 网络探测。
顶部「服务器地址」一行应显示 `http://192.168.x.x:8787`；若显示红色「还没配好服务器地址」，回到 0.3。

**B. release 包（走公网火山，T1 部署的复验）**

在仓库根出包（地址取 `app/packages/mobile/.env.production.local`，脚本会自动剔除开发者菜单、带 arm64+x86 双 ABI）：

```bash
cd app && pnpm --filter @anxin/mobile android:release
```

```bash
adb install -r app/packages/mobile/android/app/build/outputs/apk/release/app-release.apk
```

预期：`Performing Streamed Install ... Success`。装好后首页 → 网络探测 → 应显示「连通 HTTP 200」。
（另一条安装路径：把 APK 用微信发到手机，点开安装，T3 已验过。）

## 2. 主线：拍一张真实药盒 → 入箱（完成标准第 1 条）

1. 首页点「拍药盒入药箱」→ 点「拍照」→ 首次会弹相机权限，允许；
2. 对准一个**真实药盒正面**（药名+规格看得清），让文字占满画面，拍摄后**不要裁剪**，直接用；
3. 进入「正在识别（药盒）」：四条阶段文案逐条打勾（层检测 → 身份提取 → 严格匹配 → 汇合），**这段必须能看到进度**；
4. 识别完成 → 自动跳「草稿确认」页：顶部有本次原图，下面是药名/规格/剂型 + 状态徽章（如「OCR 唯一匹配确认」）；
   - 若识别有缺项，对应字段会是**空的**并标「需你填写（系统不预填猜测）」——填上才能点确认，这是设计而非 bug；
   - 若库里有多条候选，页面会让你选一条，不选就点不了确认（系统不选边）；
   - **从这一页按返回退回录入页**：应看到「识别完成：1 份草稿待确认」卡（带「去确认」「再传一张」），
     **不能**是继续转圈的「正在识别」——09-29 模拟器实测到该缺陷（单草稿分支状态机停在 processing，
     expo-router 把录入屏留在栈底），已修在 core `transitionIntakeFlow`，真机再核一次；
5. 点「确认建档」→ 提示「已确认：药品已入药箱，请手动创建计划」→ 自动进「我的药箱」；
6. 药箱列表出现该药，卡片上有通用名、规格·剂型、确认方式徽章。

**留证**：第 3、4、6 步各截图一张（文件名 `t4-01-processing.png` / `t4-02-draft.png` / `t4-03-box.png`）。

## 3. 三种失败场景（完成标准第 1 条的后半段：错误必须可见）

| # | 怎么造 | 期望在手机上看到 |
|---|---|---|
| 3.1 断网 | 手机开飞行模式后拍一张 | 「连不上服务器」卡；文案含「照片不需要重拍」+「手机与电脑要在同一个 Wi-Fi」；底部按钮为 重新上传 / 重试 |
| 3.2 服务端 500 | 关掉 0.1 那个终端里的 PostgreSQL 服务（PowerShell：`Stop-Service postgresql-x64-18`），手机再拍一张（**DB 守卫在 /api/\* 上，取不到演示用户即 500**）；测完 `Start-Service postgresql-x64-18` 恢复 | 「无法可靠识别」卡，正文是服务器返回的中文错误 + 完整重拍清单 + 黄色安全提示条（SAFETY_NOTE）；有「手动建档（不经识别）」按钮 |
| 3.3 识别不出 / PARSE_FAILED | 拍一张**没有药品文字**的东西（桌面、手心、纯色纸） | 两种都算通过：①「该对象暂不支持」卡（散装/无包装对象被层检测拦下，附 detected 标签）；②「无法可靠识别」降级卡（OCR 有字但解析不出条目）。**绝不能**出现空白页、转圈不结束、或直接报错退出 |

每条截图一张：`t4-err-offline.png` / `t4-err-500.png` / `t4-err-parse.png`。
