## 1. 实现

### 1.1 排定策略（`core/src/lib/reminder-schedule.ts`）

| 计划形态 | 触发器 | 说明 |
|---|---|---|
| active、已开始、无 endDate（长期/用完为止） | `DAILY`，每个 `times` 一条 | 应用被杀掉后闹钟仍在；不依赖下次打开应用续排 |
| active、有 endDate | `DATE` 一次性，逐日排 | 窗口 = [max(今天, startDate), min(endDate, 今天+13 天)]；每次启动/回前台向后滚动 |
| active、startDate 在未来 | `DATE` 一次性，从 startDate 起 | 到达开始日后，下次同步自动转成 DAILY |
| paused / ended | 不排 | 状态变化时同步会撤掉旧提醒 |
| 今天的时点已过（一次性档） | 跳过 | 避免刚排定就立即弹 |
| 非法 `HH:MM` / 重复时点 | 丢弃 / 去重 | 计划数据脏时不产生无效闹钟 |
| 总量 | ≤400 条，按最近触发时间保留 | Android 单应用闹钟配额留余量 |

标识统一前缀 `anxin:reminder:`，同步时只增删本应用提醒命名空间内的条目。

### 1.3 权限、渠道与前台口径

- **POST_NOTIFICATIONS**：Android 13+ 运行时权限，由 `expo-notifications` 的库 manifest 合并；引导页在 `undetermined` 时调用系统弹窗，被拒后引导去系统设置。
- **RECEIVE_BOOT_COMPLETED**：库 manifest 合并；重启后由库的 receiver 恢复闹钟。
- **SCHEDULE_EXACT_ALARM**：Android 12+ 的特殊权限；`app.json` 声明，当前本机生成的 `android/app/src/main/AndroidManifest.xml` 也已手补（`android/` 不入 git，换机 prebuild 会由 app.json 重新生成）。
- 未授予精确闹钟时，`expo-notifications` 自动降级为 `setAndAllowWhileIdle`（非精确），提醒可能被系统推迟——引导页明确说明并给跳转。
- 渠道：`medication-reminders` / 重要性 HIGH / 默认声音 / 震动 / 锁屏可见。
- **前台不展示系统通知**：应用打开时由今日页的 ReminderModal 负责提醒（含播报与三出口）；系统 handler 在前台抑制横幅，避免与页内弹窗重复。退到后台/关闭后 handler 不参与，通知照常出。

### 1.4 引导页可检测边界（必须知道）

自动可查的只有**通知权限**（`getPermissionsAsync`）。精确闹钟、电池优化白名单、自启动这三项，Expo/RN 侧没有查询 API，页面给的是：

1. 可直接打开的系统页按钮（`REQUEST_SCHEDULE_EXACT_ALARM` / `IGNORE_BATTERY_OPTIMIZATION_SETTINGS` / 厂商自启动 Activity）；
2. 打不开时回落到应用详情页，并给出本机品牌的逐步路径；
3. 从系统页返回后自动刷新通知权限并**强制重排**提醒（精确闹钟刚开时，旧的一次性闹钟需要重挂）。

因此「白名单未开时引导页正确出现」在本实现中的口径是：**通知权限未授予 → 今日页横幅 + 设置页红字状态**；电池/自启动/精确闹钟的状态无法自动判定，只保证入口常驻与路径正确。若验收要求连这三项也自动判定，需要在后续增加一个本地原生模块（`canScheduleExactAlarms` / `isIgnoringBatteryOptimizations`）——本轮未做，见 §5。

### 1.5 播报

ReminderModal 的「播报」在 M5-T7d 已接 `mobileSpeechAdapter`（`expo-speech`，zh-CN / rate 0.92，先 stop 防叠音），`wiring.ts` 在启动时注入 core。本轮无功能改动，只清理了「待接入」的过期注释。

## 5. 已知限制与待裁项

1. **特殊权限无法自动判定**（见 §1.4）：精确闹钟/电池优化/自启动只有入口与路径，没有状态回读；是否需要补本地原生模块，等用户裁定。
2. **前台提醒只在今日页**：应用停在其他页面时，页内弹窗不存在，系统通知又被前台 handler 抑制——该时点不会提醒。要覆盖「应用在前台但不在今日页」需把前台策略改成「非今日页展示系统通知」，可作为后续改进。
3. **强行停止会清空闹钟**：Android 设计，P10 只记录不计缺陷。
4. **提前打勾仍会到点提醒**：排定不读当日打卡状态；用户若在时点前就记录「已服」，到点仍会收到通知。后续可把今日已记录时点从排定中剔除。
5. **时区/时间变更**：建议回引导页点「立即重新排定提醒」。
6. **一次性窗口 14 天**：有结束日期或未来开始的计划，14 天内每次启动/回前台自动滚动；应用 14 天完全不开则窗口耗尽（长期计划走 DAILY 不受影响）。
7. **最多 400 条**：超出按最近触发时间截断，正常 4–10 个计划远低于上限。
8. **`exp+anxin-medication` 深链仍在主 manifest**：prebuild 静态写入，autolinking 排除不会删；开发者工具链的类已 0，故该深链目前无处理者（惰性）。若要求 release 包连 scheme 也没有，需要在 prebuild 后加一道 manifest 清理，属独立小改动。
9. **通知小图标/配色插件尚未应用到当前包**：`expo-notifications` 插件只在 prebuild 生效，本轮直接复用现有 `android/`，所以当前 APK 用默认应用图标；换机/prebuild 后会改用单色图标与 `#25695b`。不影响提醒功能。
