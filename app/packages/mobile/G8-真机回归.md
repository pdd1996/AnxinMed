## 2. 安装与升级

### 2.1 首次安装（3 种通道任选）

| 通道 | 步骤 | 注意 |
|---|---|---|
| `adb install`（推荐，可取证） | `adb install -r <APK>` | 需 USB 调试授权；失败先看 `adb logcat` |
| 文件传输（微信/QQ/网盘/U 盘） | 保存 APK → 文件管理器点开 → 允许「安装未知应用」 | 部分 IM 会拦截 `.apk`，可改扩展名/压缩后再传 |
| 内测分发页（可选） | 公司内网静态页放 APK + SHA-256 | 不上商店；链接仅发试点用户 |

首次启动判据：声明卡 → 登录页（「登录安心用药」）→ 管理员下发账号登录 → 今日页。**演示数据标识**必须可见（「演示抄录、覆盖有限、不构成医疗建议」）。

### 2.2 从 G7 debug 签名包升级（必测）

G7 验收用 debug keystore 签名；正式签名不同 → 直接覆盖安装会报
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`（签名不一致）。**这是预期行为，不是缺陷**。

```bash
# 卸载旧包（会清本地数据：token/字号/本地通知；服务端药箱/记录不受影响）
adb uninstall com.anxin.mobile
adb install app/packages/mobile/android/app/build/outputs/apk/release/app-release.apk
```

判据：卸载重装成功；登录后服务端数据仍在；无 `INSTALL_FAILED_*`。首次安装（无旧包）设备跳过本节。

## 5. 已知问题与豁免口径

1. **`pm clear` 在部分 ROM 被系统拒绝**（G7 实测）：验「首启态」用卸载重装，不依赖 `pm clear`。
2. **强停（设置内强制停止）会清空 AlarmManager**：属系统设计，不计入提醒缺陷；划卡/任务清理杀进程才计。
3. **过渡期明文 HTTP**：登录密码明文传输仅限演示账号 + 纯演示数据；接真实用户前必须 HTTPS（specs/14 §8）。
4. **无崩溃上报**：本轮仅靠 logcat/用户反馈；崩溃聚合属 G10 之后（错误日志已落盘，端上无上报）。
5. 真机任务**不得由代理代填**：设备不在场时保持 ⬜，G8 不得标记完成。
