### 预检查出的缺陷：系统深色下 app 不翻转（§2 第 6 条不通过）

**现象（硬证据）**：`ui_night_mode=2`、`dumpsys uimode` = `mNightMode=2 (yes)`，且 `dumpsys activity top` 里本 app 的 `mLastReportedMergedConfiguration` **带 `night` 标记**（`... 420dpi nrml long port night ...`）——原生侧确实在深色；此时 release 包**运行中**（`emu-t5a-13/14/15`）与**冷启动**（force-stop 后重开，`emu-t5a-16`）都是全白底黑字。

**已排除**：`app.json:9` 的 `userInterfaceStyle` 本就是 `"automatic"`；`android/app/src/main/res/values/styles.xml:2` 的父主题是 `Theme.AppCompat.DayNight.NoActionBar`，`res/values-night/` 存在，清单 `configChanges` 含 `uiMode`；`src/` 里没有任何手动设 `colorScheme` 的代码。所以不是「Activity 被钉在浅色」。

**我先后判错两次，都记下来免得下次再踩**：
1. 第一次说「`.dark:root` 不匹配 `isRootDarkClassSelector`，是死代码」——不成立。`normalize-selectors.js:344-359` 另有 `isRootDarkVariableSelector`，形状正是 `class(dark)+pseudo(:root)`，**当 `options.darkMode.type === "class"` 时它会编译成 `rootVariables/dark`**。
2. 第二次说「深色段在编译期就没进包」——也不成立，而且错在取证方法：我拿 `#0a0a0a`/`#26262a` 去搜，那是**心算错的十六进制**（`hsl(240 10% 3.9%)` 实际是 `#09090b`）。按正确值搜，改前的包里 `#09090b`/`#27272a`/`#a1a1aa`/`#d4d4d8` **各 1 处，全都在**。⚠️ 更一般的一条坑：**Hermes 的串表是排序去重的公共池，「某个色值在不在包里」证明不了它被编成了什么形状**——我第一次拿这个当判据，方向就是错的。

**仍未证到的那一环**：`isRootDarkVariableSelector` 要的 `options.darkMode` 是 **metro 侧 `withNativeWind(config, {...})` 传进去的选项**（`metro.config.js:60` 只传了 `input` 与 `inlineRem`），tailwind.config 的 `darkMode:["class"]` 会不会流到这里，我没证。若没流到，`.dark:root` 就落到「普通 class 选择器」分支，运行时要求祖先挂 `dark` 类——而 RN 没有 `documentElement`，没人挂，**表现正好就是现在看到的：值在包里，但永不生效**。

**已做的改动 → 已在模拟器验证通过（2026-09-30 夜，新包 `73,185,477B / 22:10`，`BUILD SUCCESSFUL in 2m 11s`）**：① `src/global.css` 的深色段改成 `@media (prefers-color-scheme: dark) { :root {…} }`——这条分支（`isRootVariableSelector` + `isDarkModeMediaQuery`）**不依赖 `darkMode` 选项**，运行时由 `runtime/native/appearance-observables.js:44-50` 的 `colorScheme.get()` 选档；② `tailwind.config.js` 去掉 `darkMode:["class"]` 与 `safelist:["dark"]`（web 靠 html 挂 `.dark` 类，RN 没有挂载点）。验证结果：深色下整页翻黑、tab 图标与文字（`useUnstableNativeVariable("--foreground")` 一族）跟着翻、无黑压黑（`emu-t5a-19/20`）；**运行中直接切系统深浅色即时翻转，不必重启**（`emu-t5a-22` 是运行中切回浅色的图，与修复前的浅色同形、无回归）；两档字号在深色下都可读。

**单变量判别（做了一半，说清边界）**：只把 `darkMode:["class"]` + `safelist:["dark"]` 加回去、CSS 保持 `@media`，重新 `expo export` 比产物哈希 → **A(`ecb2d017…`) ≠ B(`df5b0507…`)**，即该配置确实改变编译产物（改的是 `dark:` 变体的形状），所以两处都保留。**没做**第三组「只回退 CSS 到 `.dark:root`、保持无 darkMode」，因此**不下「@media 是翻转的必要条件」这种死结论**——那要各出一包看屏幕才能归因，代价是一次 2 分钟的构建 ×2。

### 顺带查出并修掉的第二个缺陷：`settings.tsx` 用原生 `Text`，颜色类整个丢失

深色一翻过来，字号切换控件就露馅了：选中态是**黑字压黑底**（用户实拍）。根因与深色无关——`src/app/(patient)/settings.tsx:1` 的 `Text` 是从 `react-native` 直接 import 的，而 `TabsTrigger` 下发文字颜色靠的是 `ui/text` 的 `TextClassContext`（`tabs.tsx:35-40` 把 `text-foreground dark:text-muted-foreground` 放进 context，只有 `ui/text` 的 `Text` 会 `useContext` 取用，见 `text.tsx` 末尾的 `Text` 实现）。用原生 `Text` 就接不上，**文字颜色退回平台默认黑色**；浅色档下黑字压白底看着正常，所以 T4 到 T5-a 一路截图都没暴露。改成从 `@/components/ui/text` 引 `Text`（它自带 `text-foreground` 基类，即使没有 context 也有颜色）。**同类漏网已扫**：`src/` 里靠 `TextClassContext` 下发样式的只有 `ui/{badge,button,card,tabs}.tsx` 四个，业务页里把裸 `Text` 当 children 塞进去的**只有这一处**（其余 `<Button>` / `<Badge>` 没有裸 Text 子节点）。
